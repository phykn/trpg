# 화면

플레이어가 한 턴을 어떻게 겪는지, 특히 **주사위를 굴리는 재미**를 웹 화면으로 만듭니다. 서버와는 [api.md](api.md)로만 이야기하고 규칙을 되풀이하지 않습니다. 고정 높이의 모바일 틀, 스크롤과 그림 없음, 서술 중 명령 잠금은 바뀌지 않는 조건입니다.

```
client/
  app/index.tsx              시작점, 저장된 game_id가 있으면 다시 열기
  screens/Title.tsx          타이틀: 언어, 이어하기, 이야기 선반
  screens/Start.tsx          주인공 만들기
  screens/Play.tsx           플레이 화면의 배치
  logic/useGame.ts           서버 상태, 명령의 생애, 복구 (3절)
  logic/reveal.ts            드러남의 시간표 (순수 함수)
  logic/fit.ts               영역에 글을 맞추는 글자 크기 (순수 함수)
  services/api.ts            HTTP와 NDJSON의 유일한 경계
  components/game/
    Header.tsx  Clocks.tsx  Self.tsx  Scene.tsx  Record.tsx
    Narration.tsx  LastRoll.tsx  Buttons.tsx  CommandBar.tsx
    RollCard.tsx  Dice.tsx  NumberLine.tsx  Chips.tsx  OddsBar.tsx
    CostCard.tsx  ClarifyCard.tsx  ConfirmCard.tsx  GrowthCard.tsx  Menu.tsx  Ending.tsx
  design/                    색, 간격, 글꼴, 움직임 시간의 토큰
  locale/ko.ts               화면이 만드는 문장
```

## 1. 원칙

| 원칙 | 뜻 |
|---|---|
| 누르지 않고 다 보인다 | 지금 판단에 필요한 것은 모두 한 화면에 늘 보임. 쪽 넘김, 탭, 펼치기, 누르면 보이는 이름, 가로 넘김, 겹쳐 여는 판이 없음 |
| 화면은 규칙을 모른다 | 확률, 합, 결정적 보정, 대가, 후보는 서버가 줌. 화면은 받은 값을 그리고 움직임만 계산함 |
| 서버의 응답이 상태다 | 응답의 `view`를 그대로 받음. 낙관적 움직임은 주사위 구름(4.4) 하나뿐이고 값을 정하지 않음 |
| 그림이 없다 | 주사위, 칸, 띠는 도형과 글자로 그리는 UI 요소 |
| 서버의 문장은 그대로 | 서버가 만든 한국어를 고치거나 자르지 않음. 화면의 문장은 `locale/ko.ts` |

누르는 것은 결정(명령, 기댈 것, 대가, 굴림)뿐입니다. 정보를 보려고 누르는 일은 없고, 연출을 건너뛰는 누름(4.5)은 있지만 누르지 않아도 같은 끝 상태에 닿습니다.

주사위의 재미는 둘입니다. **굴리는 느낌**: 결과가 정해지는 순간을 플레이어가 직접 일으키고 그 순간에 긴장이 모입니다. **내 결정이 반영된다는 느낌**: 내가 쓴 문장, 고른 방식, 아껴 둔 특성이 화면의 숫자와 결과를 바꾸었다는 것이 보입니다. 주사위 값은 서버가 `roll(seed, t)`로 정하고, 연출은 이 값이 미리 정해졌는지 숨기지도 증명하지도 않습니다. 공정함은 정해진 값이 아니라 규칙이 보인 대로 적용된다는 것(미리보기 = 실행, rule.md 3.4)에서 옵니다.

## 2. 배치

### 2.1 플레이 화면

높이는 보이는 창의 높이로 고정하고 영역은 위에서 아래로 쌓습니다. 서술 영역만 남은 높이를 받고 나머지는 내용의 높이입니다.

```
┌──────────────────────────────┐
│ 1장  등대에 오르다        ●●○ 👤 ≡│ 머리줄: 장 번호와 제목, 체력(남은 만큼 찬
│                              │   초록 점)과 주인공 아이콘, 메뉴
│ 목표 해가 지기 전에 등불실에 오르세요.│ 목표: `chapter.aim`
│ 주변 도해 기름통 녹슨 문■■□□       │ 장면: 인물·물건·장애물·장면 태그(없으면 줄 없음)
│ 장소 등대 앞                     │     장소
│ 이동 마을 부두 등불실(막힘은 흐리게)│     갈 곳
│ 위험 몰려오는 폭풍 ■■□□ 해가 진다 ■□□│ 위험: 위험 시계, 마감, 위협, 갈림
│                              │
│  서술 (200자 이하)             │ 서술 영역: 남은 높이 전부
│                              │
│ 🎲 9 대가 있는 성공 · 물보라      │ 직전 굴림
│ 녹슨 등대 문을 어떻게 할까요? [보내기]│ 입력줄(장면의 첫 대상으로 묻는 본보기)
└──────────────────────────────┘
```

- **줄마다 이름표가 있습니다.** 왼쪽 두 글자가 그 줄의 갈래이고, 갈래는 서로 겹치지 않습니다(목표 / 장면 / 위험, 주인공은 아이콘 판). 설명 문구 없이 이름표와 묶음만으로 읽히게 합니다. 비는 줄은 그리지 않습니다. 이름표 열(52px)은 머리줄(장 번호와 제목)부터 펼친 판까지 같은 자리이고, 목표부터 위험까지는 선도 간격도 없이 이어집니다.
- **칸의 색은 누구 편인지입니다.** 장애물의 칸은 금색(내가 이뤄 가는 것), 위험 줄의 칸과 이름은 모두 빨강(다가오는 나쁜 일, 위험 시계·마감·위협을 가리지 않음)입니다. 박자는 화면에 보이지 않습니다. 장면 안의 시간과 장면 사이의 시간이 두 겹으로 보이면 읽히지 않기 때문이고, 박자가 다 차서 장면이 끝나면 위험 줄의 칸이 차는 것으로만 드러납니다. 체력만 점입니다. 막힌 갈 곳은 흐리게 "(막힘)"을 붙입니다.
- **입력줄이 문장의 본보기입니다.** 추천 버튼이 없으므로 빈 입력줄은 장면의 첫 대상으로 묻습니다: 다 차지 않은 장애물이 있으면 "녹슨 등대 문을 어떻게 할까요?", 없으면 첫 인물에게 "도해에게 무엇을 할까요?", 그다음 첫 물건, 아무것도 없으면 "무엇을 할까요?". 대가를 내야 하면 대가 안내가 먼저입니다.
- **서술은 입력줄 바로 위에 붙습니다.** 서술 영역 안에서 아래로 붙여, 읽는 곳과 쓰는 곳 사이를 짧게 합니다. 한국어 줄은 낱말 사이에서만 끊습니다(`keep-all`).
- **종류는 색으로 가릅니다.** 인물, 물건, 장애물은 저마다 `colors.kind`의 색이고 이름만 씁니다(태도는 줄에 적지 않음). 좋은 태그는 금색, 나쁜 태그는 위험 색입니다.
- **늘 보이는 것과 펼치는 것.** 매 턴 바뀌거나 다음 문장에 바로 쓰는 것(목표, 체력, 위험, 장면)은 늘 보입니다. 체력은 위험 시계의 칸과 헷갈리지 않게 칸이 아니라 점으로 그립니다. 주인공 아이콘(체력 점과 한 버튼)을 누르면 머리줄 아래로 판이 내려오고, 쓰는 일이 잦은 차례로 이름, 체력(점), 상태(내 태그, 없으면 줄 없음), 능력, 특성, 소지, 기록이 있습니다. 판은 `idle`에서만 열리고, Escape나 바깥을 누르면 닫히며, 메뉴를 열면 닫힙니다. 성장할 수 있으면 아이콘에 금색 점이 붙고 성장 버튼은 판의 능력 줄에 있습니다.
- **추천 버튼은 없습니다.** 행동은 늘 입력줄에 문장으로 씁니다. 서버의 `view.buttons`는 남지만 화면은 쓰지 않습니다.

- **줄은 감싸서 늘어납니다.** 칩이 한 줄에 넘치면 다음 줄로 내려가고 서술 영역이 그만큼 줄어듭니다. 이름을 줄이거나 자르지 않습니다.
- **서술은 영역에 맞춥니다.** 서버가 서술을 200자 이하로 받으므로 넘칠 일이 드물고, 넘치면 `fit.ts`가 글자 크기를 한 단계씩(최소 `design`의 `text.min`, 13px) 줄입니다. 지난 턴의 서술은 남기지 않습니다. 첫 턴(`view.last` 없음)의 서술 자리에는 `story.premise`를 보입니다. 지난 일은 직전 굴림 줄, 장면, 기록에 결과로 남아 있습니다.
- **기록**(이름을 눌러 펼친 판)은 `journal` 가운데 지금 걸린 것을 보입니다: 지키지 않은 약속과 신세 전부, 그리고 믿는 것 중 지금 장면의 개체를 말하는 것. 고른 대가와 갈림의 선택은 결말 판(5.4)에 모입니다.
- **카드**(굴림, 되묻기, 확인, 대가, 성장)는 목표 아래부터 입력줄까지를 덮고 아래에서 올라옵니다. 걸린 시계는 굴림 카드의 결과 줄이 칸과 함께 보이므로 위험 줄은 덮여도 됩니다. 카드 안도 같은 원칙으로 모두가 한 번에 보입니다.
- **메뉴**는 머리줄 오른쪽 아이콘(≡, 도형으로 그림)으로 엽니다. 명령이 열린 상태(`idle`, `card`)에서만 누를 수 있고, 아이콘 아래로 작은 드롭다운이 내려와 화면의 나머지는 그대로 보입니다. 항목은 처음으로 하나이고, Escape나 바깥을 누르면 닫힙니다. 카드 위에 열리면 Escape는 메뉴만 닫습니다. 타이틀로 가도 `trpg.game_id`와 받은 `view`는 그대로라서 타이틀의 이어하기가 같은 판의 갈 곳으로 돌아옵니다. 서버에는 아무것도 보내지 않습니다.
- 데스크톱에서도 같은 폭(412px)의 틀을 가운데 둡니다.

### 2.2 크기 예산

320×568에서 서술 영역이 서술 200자를 13px로 담아야 합니다(px).

| 영역 | 320×568 | 412×915 |
|---|---|---|
| 머리줄 | 24 | 32 |
| 목표 | 1~2줄, 40 이하 | 1~2줄, 48 이하 |
| 장면 | 2~3줄, 64 이하 | 2~3줄, 72 이하 |
| 위험 | 1~2줄, 40 이하 | 1~2줄, 48 이하 |
| 직전 굴림 | 20 | 24 |
| 입력줄 | 40 | 52 |
| 서술 | 나머지, 최소 232(13px, 11줄 × 21자) | 나머지 |

원고에 따라 예산을 넘는 장면이 생길 수 있습니다. 320×568에서 서술 영역이 최소를 지키지 못하면 칩의 글자를 먼저 12px로, 그다음 서술의 글자를 줄입니다. QA는 뼈대 이야기에서 칩이 가장 많은 장면을 이 크기로 확인합니다(6.2).

## 3. 상태 기계

`useGame.ts`는 화면의 모든 서버 상태와 명령의 생애를 가집니다. 화면은 이 기계의 상태만 보고 그립니다.

```
loading ─► start (game_id 없음) ─► creating ─► 갈 곳
loading ─► restoring ─► 갈 곳 | narrating | blocked

idle ─ 명령 ─► sending ─┬─► 갈 곳                     (refused: reason을 입력줄 위에 보임)
                        ├─► 갈 곳                     (steps 없음: 카드)
                        └─► revealing ─► narrating ─► 갈 곳   (steps 있음)
card(roll) ─ 놓음 ─► rolling ─┬─► revealing ─► narrating ─► 갈 곳
                              └─► 갈 곳                (refused: 주사위가 값 없이 사라지고 reason을 보임)
card ─ 답 / 그만두기 ─► sending
sending | rolling ─ 응답 없음(30초) ─► stuck ─ 같은 명령 다시 ─► sending | rolling
sending | rolling ─ 409(view) ─► 갈 곳                409(incompatible) ─► blocked
sending | rolling ─ 404 ─► start                      422 ─► 갈 곳 (refused와 같게. 화면의 버그)
narrating ─ 스트림 오류 ─► narration_error ─ 다시 ─► narrating
idle | card ─ 메뉴: 처음으로 ─► start ─ 이어하기 ─► 갈 곳   (view가 있고 결말이 아닐 때)
```

**갈 곳**은 받아들인 `view`로 늘 같은 차례로 정합니다: `ending`이 있으면 `ending`, `due`가 있으면 `card(cost)`, `card`가 있으면 `card`, `growth`가 있으면 `card(growth)`, 아니면 `idle`. 409의 `view`와 다시 열기도 같습니다.

| 상태 | 명령 | 화면 |
|---|---|---|
| `idle` | 열림 | 기본 |
| `sending` | 잠김 | 입력줄에 보낸 문장, 작은 진행 표시 |
| `card` | 카드의 답과 그만두기, 또는 새 문장(카드를 버림). 대가 카드는 고르기만 | 카드 |
| `rolling` | 잠김 | 주사위가 구름 |
| `revealing` | 잠김. 누르면 끝 상태로 | 드러남(4.5) |
| `narrating` | 잠김 | 서술 단계 표시, 받은 글이 나타남 |
| `stuck` | 같은 명령 다시 보내기 버튼만 | "응답을 받지 못했습니다. 다시 보내 주세요." 주사위는 값 없이 접시에 멈춤 |
| `narration_error` | 다시 받기 버튼만 | "서술을 받지 못했습니다." 드러남의 끝 상태는 그대로 |
| `blocked` | 처음으로만 | 가운데에 "이 판은 더 이어할 수 없습니다."와 처음으로 버튼. 입력줄 없음. `trpg.game_id`는 지우지 않음 |
| `ending` | 새 게임만 | 결말 판(5.4) |

- **카드 앞의 단계**: 계획의 앞 단계를 실행하고 카드로 멈춘 응답은 `steps`와 `turn`이 있고 `view.card`도 있습니다. 화면은 그 단계들을 드러내고 서술을 받은 뒤 카드를 엽니다.
- **명령의 생애**: 명령마다 `request_id`를 하나 만들고 본문과 함께 기억합니다. 30초 안에 응답이 없으면 `stuck`이고, 같은 `request_id`와 본문으로만 다시 보냅니다. 서버의 영수증이 같은 결과를 돌려주므로 두 번 실행되지 않습니다. 다시 보내면 주사위가 다시 구르고 600ms와 30초를 다시 재며, 먼저 보낸 요청의 응답이 뒤늦게 와도 같은 응답이므로 먼저 온 것을 씁니다. 게임 만들기도 같습니다.
- **revision**: 응답의 `view.revision`을 다음 명령에 씁니다. 409에 `view`가 있으면 그것을 받아들이고, 구르던 주사위는 값 없이 사라지며, "상태가 바뀌어 다시 보였습니다"를 입력줄 위에 한 줄 보입니다. `view` 없이 `incompatible`이면 `blocked`입니다.
- **저장하는 것**: 브라우저에는 `trpg.game_id`만 둡니다. 다시 열기에 실패해도 지우지 않습니다. 404일 때만 지우고 시작 화면으로 갑니다.
- **다시 열기**: `view.last`의 단계 기록을 움직임 없이 끝 상태로 그리고(직전 굴림 줄), 서술이 캐시되어 있으면 받아서 바로 보이며, 없으면 `narrating`으로 받습니다. `view.card`가 있으면 카드를 엽니다. 드러남을 다시 연출하지 않습니다.

## 4. 굴림

### 4.1 다섯 순간

굴림이 있는 단계(`try(x ≠ player)`와 굴리는 `talk`)마다 플레이어는 다섯 순간을 지납니다. 그 뒤에 서술이 이 결과를 이야기로 씁니다. 서술은 숫자를 다시 말하지 않고 숫자가 만든 상황을 씁니다.

| 순간 | 플레이어가 보는 것 | 플레이어가 하는 것 | 겨누는 재미(fun.md) |
|---|---|---|---|
| 1. 걸린 것 | 하려는 것(`λ`, 해법이면 `label`), 위험 세 칸, 실패하면 시계에 찰 칸이 미리 그려짐과 대가의 무게, 대가 있는 성공이면 시계 +1칸과 고를 무게, 성공하면 채워질 칸("+2칸, 어울리는 방식")이나 유리한 태그 | 읽음 | 긴장 |
| 2. 결정 | 문장의 메아리와 거기서 읽은 자리(대상, 방식, 무리함, 태도), 출처가 붙은 보정 칩(`솜씨 +2`, `열쇠 +1`, `젖은 발 −1`), 기댈 것들, 세 결과의 확률 띠 | 기댈 것을 고르거나 빼고 띠의 경계가 움직이는 것을 봄 | 주체성 |
| 3. 굴림 | 손 안에서 흔들리는 주사위 둘 | 누름 | 긴장 |
| 4. 드러남 | 주사위가 하나씩 멈추고, 보정이 차례로 더해지고, 합이 결과 띠 위에 내려앉고, 결정적 칩에 이름이 붙음 | 봄 | 결과, 주체성 |
| 5. 치름 | 칸이 차는 장애물과 시계, 위기, 고를 대가 | 대가 있는 성공이면 대가를 고름 | 결과 |

모든 값은 카드의 `preview`와 단계 기록에서 옵니다. 방식과 대상은 카드에서 바꾸지 않습니다. 그것은 문장이 정한 것이고 바꾸려면 카드를 닫고 다시 말합니다. 그래서 문장의 메아리가 늘 그대로 맞습니다. 높음의 확인 카드는 따로 없고 굴림 카드가 그 역할을 합니다.

### 4.2 굴림 카드

```
┌──────────────────────────────┐
│ 녹슨 등대 문 ■■□□               │ 대상과 칸
│ "열쇠로 살살 돌려 본다"          │ 문장의 메아리
│ [솜씨] [자연스럽게]              │ 읽은 자리
├──────────────────────────────┤
│ ■ 성공 42%     녹슨 등대 문 +2칸 (어울림)│ 결과 줄: 색 표시, 이름과 확률,
│ ■ 대가 있는 성공 42% 가벼운 대가 │         그 결과의 일
│ ■ 실패 17%     몰려오는 폭풍 ■■▣□ 무거움│ ▣ = 이번에 찰 칸
│ ▕████████████▕██████▏           │ 확률 띠(글자 없음)
├──────────────────────────────┤
│ 솜씨 +2 · 물보라 −1              │ 고정 칩(0인 것은 뺌)
│ 기댈 것                         │
│ [●등대 열쇠 +1] [뱃사람 +1 장에 한 번]│ 감싸서 늘어남
│ [젖은 발 +1 쓰면 사라짐] [기대지 않음]│
├──────────────────────────────┤
│  ⚀ ⚀  눌러서 굴리기     [그만두기]│ 주사위 접시
└──────────────────────────────┘
```

- 카드의 값은 모두 `card.options`에서 고른 것의 `preview`에서 옵니다. 처음 고른 것은 `card.selected`입니다. 기댈 것을 바꾸면 그 미리보기로 바꿔 그리고 확률 띠의 경계는 250ms 동안 움직입니다. 띠의 너비가 확률이고 백분율은 결과 줄에 한 번만 적습니다. 위험 등급은 따로 적지 않습니다.
- 쓰면 사라지는 것은 기호가 아니라 글로 적습니다("장에 한 번", "쓰면 사라짐"). 누르지 않고 읽혀야 하기 때문입니다.
- 위험이 높음이면 카드의 테두리를 경고 색으로 바꾸고 결과 줄 위에 "되돌릴 수 없는 대가가 걸려 있습니다"를 둡니다.
- 320×568에서 카드는 머리줄과 시계 줄 아래 전부(500px 안팎)를 씁니다. 기댈 것 칩이 세 줄을 넘으면 칩의 글자를 12px로 줄입니다.

### 4.3 칩

`Chips.tsx` 하나가 카드, 드러남, 직전 굴림 줄에서 같은 칩을 그립니다. 칩은 `mods` 한 항목(이름과 부호 있는 값)이고 종류(`stat`, `help`, `hinder`)마다 색이 다릅니다. 방해는 서버가 이미 하나로 묶어 줍니다. 카드의 `preview.mods`와 단계 기록의 `mods`는 같은 목록이라 번호로 짝지어 같은 칩이 카드에서 드러남으로 그대로 옮겨 갑니다.

### 4.4 주사위

- `Dice.tsx`는 둥근 사각형과 눈으로 그린 주사위 둘입니다. `react-native-reanimated`로 기울기, 회전, 튀김을 움직입니다.
- **누름**: 누르는 동안 작게 흔들리고 오래 누를수록 흔들림이 커집니다(1.5초에서 더 커지지 않음). 지원하면 짧은 진동(`navigator.vibrate(10)`)을 줍니다. 짧게 누르기만 해도 굴립니다.
- **놓음**: 굴림 요청 `{card, pick}`을 보내고 주사위가 접시 위에서 구르며 면이 무작위로 바뀝니다. 유일한 낙관적 움직임이고 값을 정하지 않습니다. 굴린 뒤 카드의 결정 영역은 잠깁니다.
- **멈춤**: 응답이 왔고 놓은 뒤 600ms가 지났으면(늦은 쪽) `d1`, `d2`가 차례로 서버의 값에 멈춥니다. 값은 `steps[0]`(수락한 단계)의 `roll`입니다.
- **막힘**: `steps[0].result`가 `blocked`면 1~5단계가 없습니다. 주사위가 멈추지 않고 300ms 동안 흐려지며 사라지고, 드러난 것(`changes`의 `reveal`)의 이름이 그 자리에 나옵니다. 그 뒤 카드가 접히고(200ms) 장면 줄에 그 장애물이 생깁니다(150ms). 직전 굴림 줄은 바뀌지 않습니다. 그 뒤는 서술입니다. 숨은 것은 해 봐야 안다는 규칙을 그대로 겪게 합니다.
- **응답 없음**: 주사위는 값 없이 접시에 멈추고 `stuck`이 됩니다. 같은 굴림을 다시 보내면 같은 결과가 옵니다.

### 4.5 드러남

드러남은 결과를 한 번에 보이지 않고 **결정이 결과를 어떻게 바꾸었는지**가 보이도록 나눠서 보입니다. `logic/reveal.ts`의 `timeline(step, bands, motion) → Beat[]`이 단계 기록 하나를 시간표로 바꾸는 순수 함수이고, 화면은 시간표를 차례로 그립니다. 시간 값은 `design/`의 움직임 토큰입니다.

| # | 단계 | 시간 |
|---|---|---|
| 0 | 놓음부터 응답까지 구름 | 최소 600ms |
| 1 | `d1`, `d2`가 차례로 멈춤 | 각 250ms, `d2`는 `d1`이 시작하고 120ms 뒤에 시작 |
| 2 | `NumberLine`: `view.bands`의 눈금(1~16) 위에 결과 띠를 깔고 `d1 + d2` 자리에 점이 떨어짐 | 200ms |
| 3 | 칩이 카드의 자리에서 점으로 날아가 점을 옮김. 차례는 `mods`의 차례, 점의 중간 위치는 값을 누적한 것 | 칩마다 180ms |
| 4 | 점이 `total`에 멈추고 그 띠가 밝아지며 결과 이름이 찍힘 | 300ms |
| 5 | `decisive`의 칩에 테두리와 표시. `stat`과 `help`는 "덕분에", `hinder`는 "때문에" | 150ms |
| 6 | `changes` 가운데 `fill`은 카드 머리의 대상 칸에서(이번에 어울림으로 더 찬 마지막 칸은 다른 색), `clock`·`crisis`·`arrival`은 시계 줄에서(위기면 시계가 비며 시계 이름 옆에 "위기"가 뜸) | 칸 하나 150ms |
| 7 | 카드가 접히고 직전 굴림 줄에 합, 결과, 결정적 칩이 남음(다음 굴림까지) | 200ms |
| 8 | 남은 `changes`(태그, 상처, 흉터, 드러남, 이동, 관계, 약속, 장 전환, 결말)가 제자리에서 차례로 바뀜 | 항목마다 150ms |

- 단계는 겹치지 않고 차례로 이어집니다(`d1`과 `d2`만 겹침). 단계 기록이 여럿이면 `steps` 차례로, 굴린 단계만 1~8을 하고 굴리지 않은 단계는 6과 8만 합니다. `pay`와 `choose`의 턴도 6과 8만 합니다.
- 응답의 `view`는 받는 즉시 상태가 되지만, 6과 8이 움직이는 줄은 그 비트까지 `from` 값을 보입니다. 지난 턴의 서술은 `steps`가 오는 순간 지웁니다.
- 결과 이름은 `locale/ko.ts`의 낱말(성공, 대가 있는 성공, 실패)입니다.
- 보정 칩이 둘이면 2초 안팎입니다. 어디를 눌러도 남은 연출을 건너뛰고 끝 상태(`view` 그대로)로 갑니다.
- `prefers-reduced-motion`이면 구름, 날아감, 칸 차기의 움직임 없이 각 단계의 끝 상태를 차례로 100ms씩 보입니다.
- 결정적 칩은 서버가 정해 주므로 화면은 "없었다면"을 계산하지 않습니다.

### 4.6 대가

`view.due`가 있으면 서술이 다 보인 뒤 `CostCard`가 열립니다. 후보마다 이름, 무게, 효과를 `view.due`의 차례로 보이고 하나를 누르면 그 `pay` 행동을 보냅니다. 그만두기가 없고, 입력줄은 열려 있지만 서버는 `try(player)`만 받으며 안내 문장은 "먼저 대가를 고르세요"입니다. 고르는 것도 내 결정이므로 고른 대가는 결말 판의 목록에 남습니다.

### 4.7 하지 않는 것

이동, 살펴보기, 집기, 건네기, 잡담, 공짜 화제, 선택, 장면 넘김에는 주사위가 나오지 않습니다. 결과가 정해진 행동에 주사위를 보이면 주사위가 뜻을 잃기 때문입니다.

| 하지 않는 것 | 이유 |
|---|---|
| 다시 굴리기, 굴림을 사는 것 | 주사위가 가볍게 여겨지고 실패가 상황을 바꾸지 못함 |
| 확률을 숨기는 것 | 긴장은 결과의 불확실함에서 오고 걸린 것을 아는 데서 커짐 |
| 서술이 숫자를 말하는 것 | 숫자는 드러남이 이미 보였음 |
| 카드에서 방식과 대상을 바꾸는 것 | 4.1 |
| 주사위 값을 미리 증명하는 장치 | 공정함은 규칙의 적용에서 옴 |

## 5. 그 밖의 화면

### 5.1 서술

- 서술 요청은 명령의 응답을 받자마자 시작하고, 드러남이 끝날 때까지 받은 글을 쥐고 있습니다. 드러나는 동안 모델이 씁니다.
- 스트림의 `stage`를 서술 영역에 작게 보입니다("쓰는 중", "확인하는 중", "다시 쓰는 중"). `attempt`는 쓰지 않습니다.
- `text`가 오면 글자가 차례로 나타납니다(초당 60자, 누르면 바로 다 보임). 글자 크기는 다 나타난 글로 먼저 정해 두어 나타나는 동안 바뀌지 않습니다. 글이 다 보이고 `done`을 받으면 `narrating`이 끝납니다.
- `error`는 드러남이 끝난 뒤에 보이고, 고정 문구 아래 서버의 `message`를 작게 둡니다. 스트림이 끊기거나 2xx가 아니면 `message` 없는 `error`와 같습니다. 화면 쪽 시간 제한은 없습니다(상한은 서버의 것, engine.md 8절).
- 장 전환이나 결말의 턴은 서술 아래에 되돌아보기(`/chapters/{k}/recap`, api.md 4절의 `k`)를 이어 보입니다. 서술의 `done` 뒤에 요청하고(그동안도 `narrating`), 실패하면 서술과 같은 `narration_error`입니다.
- `done`의 태그 이름으로 나 줄과 칩의 이름을 바꿉니다.

### 5.2 되묻기와 확인

`ClarifyCard`는 선택지(많아야 셋)와 그만두기, `ConfirmCard`는 고를 것의 이름과 효과, 고른다와 그만두기입니다. 둘 다 주사위가 없습니다.

### 5.3 성장

`view.growth`가 있으면 서술이 끝난 뒤 `GrowthCard`가 열립니다. 성장 행동마다 버튼이 있고 "나중에"를 누르면 닫힙니다. 닫혀 있는 동안 나 줄에 "성장 1"이 보이고 그것을 누르면 다시 엽니다. 성장은 결정이라 누름이 있습니다.

### 5.4 결말

`view.ending`이 놓이면 결말 서술과 되돌아보기 뒤에 머리줄 아래 전부를 결말 판으로 바꿉니다. 결말의 제목, 장마다 되돌아보기(`view.recaps`의 장마다 하나, 100자 이하), 고른 대가와 갈림의 선택 목록(`journal`)이 한 판에 들어갑니다. 새 게임은 새로 만들고 `trpg.game_id`를 바꿉니다.

### 5.5 시작

시작은 두 화면입니다. **타이틀**(`Title.tsx`): 위에 언어 칸(한국어, English. 지금은 한국어만), 주사위 두 개(도형), 제목과 그 아래 금색 선. 아래에 이야기 한 장(제목과 전제, 여럿이면 ‹ ›로 넘김), 그 아래 그 이야기로 할 일: 저장된 판이 이 이야기이고 결말이 아니면 이어하기(이름, 장, 장소. 주 버튼), 그리고 새로 시작(이어하기가 없으면 주 버튼). 처음 보이는 이야기는 저장된 판의 이야기입니다. 새로 시작은 **만들기**(`Start.tsx`)로 갑니다. 맨 아래에 버전과 저작권 한 줄. 만들기: 둥근 뒤로 버튼과 이야기 제목, 이름(입력 칸, 10자까지. 비우면 플레이스홀더인 "주인공"), 능력치("능력치 n/합" 아래 방식이 한 줄에 하나씩 이름과 짧은 설명, 특성과 같은 높이, 0에서 시작해 ◀ 값 ▶로 나눠 줌. 합을 넘거나 원고의 가장 큰 값을 넘으면 ▶가 꺼짐), 특성("특성 n/pick" 아래 한 줄에 하나씩, 이름과 글), 시작하기. 전제는 타이틀에서 이미 보였으므로 되풀이하지 않습니다. 능력치를 다 쓰고 특성을 `pick`개 고르면 시작하기가 열리고, 누르면 `POST /games`를 보내고 플레이 화면으로 갑니다.

## 6. 검사

### 6.1 자동 테스트

| 대상 | 테스트 |
|---|---|
| `useGame` | 전이: 카드, 카드 앞의 단계, 굴림, 대가 카드, 409(view 있음, incompatible), 응답 없음 뒤 같은 `request_id`, 다시 열기에서 `trpg.game_id` 유지 |

| `api.ts` | NDJSON 조각이 줄 경계에서 나뉘어 와도 같은 사건 |
| 카드 | 기댈 것을 바꾸면 그 미리보기를 그림, `selected`가 처음 고른 것, 높음의 경고 |

화면 테스트는 가짜 `api`로 돕니다. 규칙이 화면에 없으므로 확률이나 합을 화면에서 계산하는 테스트는 없습니다.
