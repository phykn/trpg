# 화면 구현

[experience.md](experience.md)의 경험을 웹 화면으로 만듭니다. 서버와는 [engine.md](engine.md) 8절의 API로만 이야기합니다. 지금의 코드는 참고만 했고, 프로젝트의 불변식(고정 높이 모바일 틀, 스크롤과 그림 없음, 서술 중 명령 잠금)은 그대로 따릅니다.

```
client/
  app/index.tsx              시작점, 저장된 game_id가 있으면 다시 열기
  screens/Start.tsx          이야기 고르기, 주인공 만들기
  screens/Play.tsx           플레이 화면의 배치
  logic/useGame.ts           서버 상태, 명령의 생애, 복구 (3절)
  logic/reveal.ts            드러남의 시간표 (순수 함수)
  logic/fit.ts               영역에 글을 맞추는 글자 크기 (순수 함수)
  services/api.ts            HTTP와 NDJSON의 유일한 경계
  components/game/
    Header.tsx  Clocks.tsx  Self.tsx  Scene.tsx  Record.tsx
    Narration.tsx  LastRoll.tsx  Buttons.tsx  CommandBar.tsx
    RollCard.tsx  Dice.tsx  NumberLine.tsx  Chips.tsx  OddsBar.tsx
    CostCard.tsx  ClarifyCard.tsx  ConfirmCard.tsx  GrowthCard.tsx  Ending.tsx
  design/                    색, 간격, 글꼴, 움직임 시간의 토큰
  locale/ko.ts               화면이 만드는 문장
```

## 1. 원칙

| 원칙 | 뜻 |
|---|---|
| 누르지 않고 다 보인다 | 지금 판단에 필요한 것은 모두 한 화면에 늘 보임. 쪽 넘김, 탭, 펼치기, 누르면 보이는 이름, 가로 넘김, 겹쳐 여는 판이 없음 |
| 화면은 규칙을 모른다 | 확률, 합, 결정적 보정, 대가, 후보는 서버가 줌. 화면은 받은 값을 그리고 움직임만 계산함 |
| 서버의 응답이 상태다 | 응답의 `view`를 그대로 받음. 낙관적 움직임은 주사위 구름(4.3) 하나뿐이고 값을 정하지 않음 |
| 그림이 없다 | 주사위, 칸, 띠는 도형과 글자로 그리는 UI 요소 |
| 서버의 문장은 그대로 | 서버가 만든 한국어를 고치거나 자르지 않음. 화면의 문장은 `locale/ko.ts` |

누르는 것은 결정(명령, 기댈 것, 대가, 굴림)뿐입니다. 정보를 보려고 누르는 일은 없습니다. 연출을 건너뛰는 누름(4.4)은 있지만, 누르지 않아도 같은 끝 상태에 닿습니다.

## 2. 배치

### 2.1 플레이 화면

높이는 보이는 창의 높이로 고정하고, 영역은 위에서 아래로 쌓습니다. 서술 영역만 남은 높이를 받고 나머지는 내용의 높이입니다.

```
┌──────────────────────────────┐
│ 1장 등대에 오르다 · 등대 앞      │ 머리줄
│ 몰려오는 폭풍 ■■□□ 해가 진다 ■□□│ 시계 줄: 위험 시계, 마감, 위협, 갈림
│ 무너지는 다리 ■□□               │
│ 힘1 솜씨2 꾀1 말0 · 상처 ■□□ · 박자2│ 나 줄: 방식, 상처, 박자,
│ 뱃사람 · 손재주(씀) · 젖은 발 · 흉터 떨림│       특성(쓴 것은 흐리게), 태그, 흉터
│ 도해(경계) · 기름통 · 녹슨 문 ■■□□ │ 장면 줄: 인물(태도), 물건, 장애물(칸),
│ → 마을 → 부두                   │       갈 곳
│ 약속: 도해에게 등대 불 · 앎: 열쇠 │ 기록 줄: 약속과 신세, 지금 장면에 닿는 믿음
├──────────────────────────────┤
│                              │
│  서술 (200자 이하)             │ 서술 영역: 남은 높이 전부
│                              │
├──────────────────────────────┤
│ 🎲 9 대가 있는 성공 · 물보라 때문에│ 직전 굴림
│ [열쇠로 자물쇠를 연다 🎲]       │ 추천 버튼 셋
│ [도해에게 등대 기름을 묻는다]    │
│ [마을로 간다]                  │
│ 무엇을 할까요?          [보내기] │ 입력줄
└──────────────────────────────┘
```

- **줄은 감싸서 늘어납니다.** 칩이 한 줄에 넘치면 다음 줄로 내려가고 서술 영역이 그만큼 줄어듭니다. 이름을 줄이거나 자르지 않습니다.
- **서술은 영역에 맞춥니다.** 서버가 서술을 200자 이하로 받으므로(engine.md 5.2) 넘칠 일이 드물고, 넘치면 `fit.ts`가 글자 크기를 한 단계씩(최소 `design`의 `text.min`, 13px) 줄입니다. 지난 턴의 서술은 남기지 않습니다. 지난 일은 직전 굴림 줄, 장면 줄, 기록 줄에 결과로 남아 있습니다.
- **기록 줄**은 `journal` 가운데 지금 걸린 것을 보입니다: 지키지 않은 약속과 신세 전부, 그리고 믿는 것 중 지금 장면의 개체를 말하는 것(`journal`의 표시). 장면에 닿지 않는 믿음은 그 개체가 장면에 나오면 다시 보입니다. 고른 대가와 갈림의 선택은 결말 판(5.4)에 모입니다.
- **카드**(굴림, 되묻기, 확인, 대가, 성장)는 나 줄부터 입력줄까지를 덮고 아래에서 올라옵니다. 머리줄과 시계 줄은 덮지 않습니다. 카드가 떠 있어도 걸린 시계가 보여야 하기 때문입니다. 카드 안도 같은 원칙으로 모두가 한 번에 보입니다.
- 데스크톱에서도 같은 폭(412px)의 틀을 가운데 둡니다.

### 2.2 크기 예산

320×568에서 서술 영역이 서술 200자를 13px로 담아야 합니다. 다른 영역의 예산은 이렇습니다(px).

| 영역 | 320×568 | 412×915 |
|---|---|---|
| 머리줄 | 24 | 32 |
| 시계 줄 | 1~2줄, 40 이하 | 1~2줄, 48 이하 |
| 나 줄 | 2줄, 40 | 2줄, 48 |
| 장면 줄 | 2줄, 40 | 2~3줄, 64 이하 |
| 기록 줄 | 1~2줄, 36 이하 | 1~2줄, 44 이하 |
| 직전 굴림 | 20 | 24 |
| 추천 버튼 | 3 × 32 | 3 × 44 |
| 입력줄 | 40 | 52 |
| 서술 | 나머지, 최소 232(13px, 11줄 × 21자) | 나머지 |

원고에 따라 예산을 넘는 장면(인물과 물건이 많은 곳)이 생길 수 있습니다. 320×568에서 서술 영역이 최소를 지키지 못하면 칩의 글자를 먼저 12px로, 그다음 서술의 글자를 줄입니다. QA는 뼈대 이야기에서 칩이 가장 많은 장면을 이 크기로 확인합니다(6.2).

## 3. 상태 기계

`useGame.ts`는 화면의 모든 서버 상태와 명령의 생애를 가집니다. 화면은 이 기계의 상태만 보고 그립니다.

```
loading ─► start (game_id 없음) ─► creating ─► idle
loading ─► restoring ─► idle | card | narrating | blocked

idle ─ 명령 ─► sending ─┬─► refused ─► idle
                        ├─► card                       (steps 없음)
                        └─► revealing ─► narrating ─► idle | card | ending
                                                       (steps 있음, 끝에 view.card가 있으면 card)

card(roll) ─ 놓음 ─► rolling ─► revealing ─► narrating ─► …
card ─ 답 / 그만두기 ─► sending
sending ─ 응답 없음 ─► stuck ─ 같은 명령 다시 ─► sending
narrating ─ 스트림 오류 ─► narration_error ─ 다시 ─► narrating
```

| 상태 | 명령 | 화면 |
|---|---|---|
| `idle` | 열림 | 기본 |
| `sending` | 잠김 | 입력줄에 보낸 문장, 작은 진행 표시 |
| `card` | 카드의 답과 그만두기, 또는 새 문장(카드를 버림) | 카드 |
| `rolling` | 잠김 | 주사위가 구름 |
| `revealing` | 잠김. 누르면 끝 상태로 | 드러남(4.4) |
| `narrating` | 잠김 | 서술 단계 표시, 받은 글이 나타남 |
| `stuck` | 같은 명령 다시 보내기만 | "응답을 받지 못했습니다. 다시 보내 주세요." |
| `narration_error` | 다시 받기만 | "서술을 받지 못했습니다." |
| `blocked` | 새 게임만 | 저장이 호환되지 않음. `trpg.game_id`는 지우지 않음 |
| `ending` | 새 게임만 | 결말 판(5.4) |

- **카드 앞의 단계**: 계획의 앞 단계를 실행하고 카드로 멈춘 응답은 `steps`와 `turn`이 있고 `view.card`도 있습니다(engine.md 8.4). 화면은 그 단계들을 드러내고 서술을 받은 뒤 카드를 엽니다(experience.md 3절).
- **명령의 생애**: 명령마다 `request_id`를 하나 만들고 본문과 함께 기억합니다. 응답이 없으면 같은 `request_id`와 본문으로만 다시 보냅니다. 서버의 영수증이 같은 결과를 돌려주므로 두 번 실행되지 않습니다. 게임 만들기도 같습니다.
- **revision**: 응답의 `view.revision`을 다음 명령에 씁니다. 409에 `view`가 있으면 그것을 받아들이고 그 `view`에 맞는 상태(`idle` 또는 `card`)로 갑니다. `view` 없이 `incompatible`이면 `blocked`입니다.
- **저장하는 것**: 브라우저에는 `trpg.game_id`만 둡니다. 다시 열기에 실패해도 지우지 않습니다. 404일 때만 지우고 시작 화면으로 갑니다.
- **다시 열기**: `view.last`의 단계 기록을 움직임 없이 끝 상태로 그리고(직전 굴림 줄), 서술이 캐시되어 있으면 받아서 바로 보이며, 없으면 `narrating`으로 받습니다. `view.card`가 있으면 카드를 엽니다(X6).

## 4. 굴림

### 4.1 굴림 카드의 배치

```
┌──────────────────────────────┐
│ 녹슨 등대 문 ■■□□               │ 대상과 칸
│ "열쇠로 살살 돌려 본다"          │ 문장의 메아리
│ [솜씨] [자연스럽게]              │ 읽은 자리
├──────────────────────────────┤
│ 위험 보통                       │
│ 성공  녹슨 등대 문 +2칸 (어울림)  │
│ 대가  가벼운 대가를 고름          │
│ 실패  몰려오는 폭풍 ■■▣□ · 무거운 대가│ ▣ = 이번에 찰 칸
├──────────────────────────────┤
│ 솜씨 +2 · 물보라 −1              │ 고정 칩
│ 기댈 것                         │
│ [●등대 열쇠 +1] [뱃사람 +1 장에 한 번]│ 감싸서 늘어남
│ [젖은 발 +1 쓰면 사라짐] [기대지 않음]│
│ ▕실패 17%▕대가 있는 성공 42%▕성공 42%▏│ 확률 띠
├──────────────────────────────┤
│  ⚀ ⚀  누르고 있다 놓으세요  [그만두기]│ 주사위 접시
└──────────────────────────────┘
```

- 카드의 값은 모두 `card.options`에서 고른 것의 `preview`에서 옵니다. 처음 고른 것은 `card.selected`입니다. 기댈 것을 바꾸면 그 미리보기로 바꿔 그리고 확률 띠의 경계는 250ms 동안 움직입니다.
- 쓰면 사라지는 것은 기호가 아니라 글로 적습니다("장에 한 번", "쓰면 사라짐"). 누르지 않고 읽혀야 하기 때문입니다.
- 위험이 높음이면 카드의 테두리를 경고 색으로 바꾸고, 결과 줄 위에 "되돌릴 수 없는 대가가 걸려 있습니다"를 둡니다.
- 320×568에서 카드는 머리줄과 시계 줄 아래 전부(500px 안팎)를 씁니다. 기댈 것 칩이 세 줄을 넘으면 칩의 글자를 12px로 줄입니다.

### 4.2 칩

`Chips.tsx` 하나가 카드, 드러남, 직전 굴림 줄에서 같은 칩을 그립니다. 칩은 서버의 `mods` 한 항목(이름과 부호 있는 값)이고, 종류(`stat`, `help`, `hinder`)마다 색이 다릅니다. 방해는 서버가 이미 하나로 묶어 줍니다(engine.md 8.3). 같은 칩이 카드에서 드러남으로 그대로 옮겨 가야 "내가 고른 것이 여기 더해진다"가 보입니다.

### 4.3 주사위

- `Dice.tsx`는 둥근 사각형과 눈으로 그린 주사위 둘입니다. `react-native-reanimated`로 기울기, 회전, 튀김을 움직입니다.
- **누름**: 누르는 동안 작게 흔들리고 오래 누를수록 흔들림이 커집니다(1.5초에서 더 커지지 않음). 지원하면 짧은 진동(`navigator.vibrate(10)`)을 줍니다.
- **놓음**: 굴림 요청(`{card, pick}`)을 보내고, 주사위가 접시 위에서 구르며 면이 무작위로 바뀝니다. 이것이 유일한 낙관적 움직임이고 값을 정하지 않습니다.
- **멈춤**: 응답이 오고 최소 600ms가 지나면 `d1`, `d2`가 차례로 서버의 값에 멈춥니다. 응답의 단계 기록 중 이 카드의 단계(`roll`이 있는 첫 단계)의 값입니다.
- **막힘**: 그 단계의 결과가 `blocked`면 주사위가 멈추지 않고 흐려지며 사라지고, 드러난 것(`changes`의 `reveal`)이 그 자리에 나옵니다.
- **응답 없음**: 주사위는 값 없이 접시에 멈추고 `stuck`이 됩니다. 같은 굴림을 다시 보내면 같은 결과가 옵니다.

### 4.4 드러남

`logic/reveal.ts`의 `timeline(step, bands, motion) → Beat[]`이 단계 기록 하나를 시간표로 바꾸는 순수 함수입니다. 화면은 시간표를 차례로 그립니다. 시간 값은 `design/`의 움직임 토큰이고 experience.md 6절을 따릅니다.

1. 주사위 둘이 멈춤.
2. `NumberLine`: `view.bands`의 눈금(1~16) 위에 결과 띠를 깔고 `d1 + d2` 자리에 점이 떨어짐.
3. 칩이 카드의 자리에서 점으로 날아가 점을 옮김. 차례는 `mods`의 차례.
4. 점이 `total`에 멈추고, 그 띠가 밝아지며 결과 이름이 찍힘.
5. `decisive`의 칩에 테두리와 표시. 도움과 방식은 "덕분에", 방해는 "때문에".
6. `changes`를 차례로: 장애물 칸이 차고(어울림으로 더 찬 칸은 다른 색), 시계가 차고, 위기면 시계가 비며 위기 이름이 뜨고, 태그와 상처가 바뀜. 칸과 시계는 제자리(시계 줄, 장면 줄, 나 줄)에서 찹니다.
7. 단계 기록이 여럿이면 굴린 단계만 1~6을 하고 굴리지 않은 단계는 6만 짧게 합니다.

드러남이 끝나면 카드가 접히고, 직전 굴림 줄에 합, 결과, 결정적 칩이 남습니다. 다음 굴림까지 그대로 있습니다.

**움직임 줄이기**: `prefers-reduced-motion`이면 구름, 날아감, 칸 차기의 움직임 없이 각 단계의 끝 상태를 차례로 100ms씩 보입니다(experience.md 6절).

### 4.5 대가

`view.due`가 있으면 드러남이 끝난 뒤 `CostCard`가 열립니다. 후보마다 이름, 무게, 효과를 보이고 하나를 누르면 그 `pay` 행동을 보냅니다. 그만두기가 없고, 입력줄은 열려 있지만 서버는 `try(player)`만 받습니다(rule.md 2절). 입력줄 안내 문장은 "먼저 대가를 고르세요"입니다.

## 5. 그 밖의 화면

### 5.1 서술

- 서술 요청은 명령의 응답을 받자마자 시작하고, 드러남이 끝날 때까지 받은 글을 쥐고 있습니다.
- 스트림의 `stage`를 서술 영역에 작게 보입니다("쓰는 중", "확인하는 중", "다시 쓰는 중").
- `text`가 오면 글자가 차례로 나타납니다(초당 60자, 누르면 바로 다 보임). 글자 크기는 다 나타난 글로 먼저 정해 두어 나타나는 동안 바뀌지 않습니다.
- 장 전환이나 결말의 턴은 서술 아래에 되돌아보기(`/chapters/{k}/recap`)를 이어 보입니다. 둘의 길이는 서버가 영역에 맞게 제한합니다(engine.md 5.2).
- `done`의 태그 이름으로 나 줄과 칩의 이름을 바꿉니다.

### 5.2 되묻기와 확인

`ClarifyCard`는 선택지(많아야 셋)와 그만두기, `ConfirmCard`는 고를 것의 이름과 효과, 고른다와 그만두기입니다. 둘 다 주사위가 없습니다.

### 5.3 성장

`view.growth`가 있으면 서술이 끝난 뒤 `GrowthCard`가 열립니다. 성장 행동마다 버튼이 있고 "나중에"를 누르면 닫힙니다. 닫혀 있는 동안 나 줄에 "성장 1"이 보이고, 그것을 누르면 다시 엽니다. 성장은 결정이라 누름이 있습니다.

### 5.4 결말

`view.ending`이 놓이면 결말 서술 뒤에 머리줄 아래 전부를 결말 판으로 바꿉니다. 결말의 제목, 장마다 되돌아보기(`view.recaps`의 장마다 하나, 100자 이하), 고른 대가와 갈림의 선택 목록(`journal`)이 한 판에 들어갑니다. 새 게임은 새로 만들고 `trpg.game_id`를 바꿉니다.

### 5.5 시작

`Start.tsx`는 한 화면에 이야기 목록, 방식 배치, 특성 고르기를 둡니다. 이야기를 고르면 그 전제와 방식 값, 특성 후보가 같은 화면에 나옵니다. 방식 값은 네 방식 칸에 눌러서 차례로 놓고, 특성은 `pick`개를 고릅니다. 만들기를 누르면 `POST /games`를 보내고 플레이 화면으로 갑니다.

## 6. 검사

### 6.1 자동 테스트

| 대상 | 테스트 |
|---|---|
| `useGame` | 전이: 카드, 카드 앞의 단계, 굴림, 409(view 있음, incompatible), 응답 없음 뒤 같은 `request_id`, 다시 열기에서 `trpg.game_id` 유지 |
| `reveal.ts` | 단계 기록 → 시간표: 칩 차례, 결정적 표시, 막힘, 움직임 줄이기 |
| `fit.ts` | 200자가 320×568의 최소 서술 영역에 13px로 들어감, 칩 줄이 늘면 글자가 줄어듦 |
| `api.ts` | NDJSON 조각이 줄 경계에서 나뉘어 와도 같은 사건 |
| 카드 | 기댈 것을 바꾸면 그 미리보기를 그림, `selected`가 처음 고른 것, 높음의 경고 |

화면 테스트는 가짜 `api`로 돕니다. 규칙이 화면에 없으므로 확률이나 합을 화면에서 계산하는 테스트는 없습니다.

### 6.2 실제 화면

두 모델을 켠 서버와 함께 412×915, 데스크톱 폭, 320×568에서 다음을 직접 해 보고, 번호를 붙인 턴과 스크린숏을 `qa_test/agency/<run>/`에 남깁니다.

| 흐름 | 확인할 것 |
|---|---|
| 한 화면 | 매 턴의 스크린숏에 스크롤, 잘린 글, 겹침이 없음. 칩이 가장 많은 장면과 기댈 것이 가장 많은 카드 |

| 굴림 | 기댈 것을 바꾸면 띠가 움직임, 누름과 놓음, 드러남의 차례, 결정적 칩 |
| 연쇄 | 굴리지 않는 단계의 드러남과 서술 뒤에 굴림 카드 |

| 성장, 결말 | 장 전환의 되돌아보기, 성장 카드, 결말 판 |

통과한 테스트는 재미를 보여 주지 않습니다. 굴림이 재미있는지는 experience.md 7절의 지표와 fun.md F12로 봅니다.
