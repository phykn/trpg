# 플레이 경험

한 턴을 플레이어가 어떻게 겪는지, 특히 **주사위를 굴리는 재미**를 정하고, 그 경험이 엔진에 요구하는 것을 모읍니다. [engine.md](engine.md)는 이 문서의 요구(5절)를 만족하도록 프로토콜을 정하고, [ui.md](ui.md)는 이 경험을 화면으로 만듭니다. 재미의 요소와 측정은 [fun.md](../theory/fun.md)입니다.

## 1. 목표

주사위의 재미는 두 가지입니다.

1. **굴리는 느낌**: 결과가 정해지는 순간을 플레이어가 직접 일으키고, 그 순간에 긴장이 모입니다.
2. **내 결정이 반영된다는 느낌**: 내가 쓴 문장, 고른 방식, 아껴 둔 특성이 화면의 숫자와 결과를 바꾸었다는 것이 보입니다.

주사위 값은 서버가 `H(seed, t)`로 정합니다(rule.md 3.1). 연출은 이 값이 미리 정해졌는지 숨기지도 증명하지도 않습니다. 플레이어가 누르면 주사위가 구르고, 서버의 값에 멈춥니다. 공정함은 정해진 값이 아니라 **규칙이 보인 대로 적용된다는 것**(미리보기 = 실행, rule.md 3.4)에서 옵니다.

## 2. 굴림의 다섯 순간

굴림이 있는 단계(`try(x ≠ player)`와 굴리는 `talk`)마다 플레이어는 다섯 순간을 지납니다.

| 순간 | 플레이어가 보는 것 | 플레이어가 하는 것 | 겨누는 재미(fun.md 2절) |
|---|---|---|---|
| 1. 걸린 것 | 무엇을 하려는지, 위험, 실패하면 무엇을 치르는지, 성공하면 무엇이 생기는지 | 읽음 | 긴장 |
| 2. 결정 | 내 문장에서 읽은 것과 그 보정, 세 결과의 확률 | 기댈 것을 고르거나 빼고, 확률이 바뀌는 것을 봄 | 주체성 |
| 3. 굴림 | 손 안에서 흔들리는 주사위 두 개 | 누르고 있다 놓음 | 긴장 |
| 4. 드러남 | 주사위가 하나씩 멈추고, 보정이 차례로 더해지고, 합이 결과 띠 위에 내려앉음 | 봄 | 결과, 주체성 |
| 5. 치름 | 칸이 차는 시계와 장애물, 고를 대가 | 대가 있는 성공이면 대가를 고름 | 결과 |

그 뒤에 서술이 이 결과를 이야기로 씁니다. 서술은 숫자를 다시 말하지 않고, 숫자가 만든 상황을 씁니다.

### 2.1 걸린 것

굴림 카드의 윗부분입니다. 모두 미리보기(rule.md 3.4)에서 옵니다.

- **하려는 것**: 행동 이름 `λ`. 해법이면 원고의 `label`.
- **위험**: 낮음, 보통, 높음 세 칸. 높음이면 카드 전체의 테두리와 굴림 버튼이 달라지고 "되돌릴 수 없는 대가"를 말합니다. 높음의 확인 카드(engine G5)가 따로 나오지 않고 이 카드가 그 역할을 합니다.
- **실패하면**: 시계 이름과 칸, 그리고 "+1칸"이나 "+2칸"이 칸 위에 미리 그려짐. 복잡화는 무게만 말합니다("가벼운 대가", "무거운 대가").
- **대가 있는 성공이면**: 시계 +1칸, 그리고 고르게 될 대가의 무게.
- **성공하면**: 장애물이면 채워질 칸 수("+2칸, 어울리는 방식"), 그 밖이면 "유리한 태그".

### 2.2 결정

카드의 가운데입니다. 이 영역이 "내 결정이 반영된다"를 만듭니다.

- **문장의 메아리**: 플레이어가 쓴 문장을 한 줄로 다시 보이고, 그 아래에 문장에서 읽은 것을 칩으로 늘어놓습니다: 대상, 방식, 무리함, 태도. 버튼으로 시작한 단계는 버튼 이름을 메아리로 씁니다.
- **보정의 칩**: 숫자 하나하나에 출처를 붙입니다. `솜씨 +2`, `열쇠 +1`, `젖은 발 −1`. 방해의 원자가 여럿이어도 방해는 −1 하나이고, 칩은 그 원자들의 이름을 묶어 보입니다(rule J2).
- **기댈 것 고르기**: 기댈 수 있는 것(유리한 태그, 쓰지 않은 특성, 지닌 물건, 믿는 것, 유대)을 칩으로 보이고, 하나를 고르거나 빼게 합니다. 쓰면 사라지는 것(태그, 이번 장의 특성)은 그렇다고 표시합니다. 문장이 기댈 것을 말했으면 그것이 골라진 채로 열립니다.
- **확률 띠**: 실패, 대가 있는 성공, 성공을 세 칸의 띠로, 너비가 확률입니다(fun.md 4.1). 기댈 것을 바꾸면 띠의 경계가 움직입니다. 숫자 백분율은 띠 위에 작게 둡니다.

방식과 대상은 카드에서 바꾸지 않습니다. 그것은 문장이 정한 것이고, 바꾸려면 카드를 닫고 다시 말합니다. 그래서 문장으로 정한 것과 카드에서 고른 것이 섞이지 않고, 문장의 메아리가 늘 그대로 맞습니다.

### 2.3 굴림

- 주사위 두 개가 카드 아래 접시에 놓여 있습니다. 누르고 있는 동안 흔들리고, 놓으면 굴러갑니다. 짧게 누르기만 해도 굴립니다.
- 놓는 순간 요청이 나갑니다. 주사위는 응답이 올 때까지 구르고, 응답이 오면 최소 구르는 시간을 채운 뒤 서버의 값으로 멈춥니다.
- 굴린 뒤에는 카드의 결정 영역이 잠기고 기댈 것을 바꿀 수 없습니다.

### 2.4 드러남

드러남은 결과를 한 번에 보이지 않고, **결정이 결과를 어떻게 바꾸었는지**가 보이도록 나눠서 보입니다.

1. `d₁`, `d₂`가 차례로 멈춥니다.
2. 두 눈의 합이 확률 띠 아래의 눈금(1~16)에 점으로 떨어집니다.
3. 보정 칩이 하나씩 그 점으로 날아가 점을 옮깁니다(`+2`, `+1`, `−1`). 칩마다 점이 움직입니다.
4. 점이 멈춘 칸이 결과입니다. 결과 이름이 크게 찍힙니다.
5. **결정적 칩**: 어떤 칩을 빼면 결과의 칸이 달라졌을 때, 그 칩에 표시를 남깁니다. "열쇠 덕분에 성공", "젖은 발 때문에 실패". 결정이 결과를 바꾼 순간을 이름으로 보이는 장치입니다.

모든 보정이 서버의 `mods`에서 오므로(rule.md 3.2) 드러남은 화면이 계산을 지어내지 않습니다. 결정적 칩도 서버가 단계 기록의 `decisive`로 정해 줍니다(engine.md 8.3).

### 2.5 치름

- 장애물이 대상이면 칸이 하나씩 찹니다. 어울리는 방식으로 더 찬 칸은 "어울림"이라고 붙입니다.
- 시계가 오르면 칸이 차고, 다 차면 위기가 그 자리에서 일어납니다(시계가 비고 위기의 이름이 뜸).
- 대가 있는 성공에서 고를 대가가 있으면 대가 카드가 열립니다. 후보는 둘이나 셋이고 무게와 효과의 이름을 보입니다. 플레이어가 고르기 전에는 다른 행동을 할 수 없습니다(rule 3.4). 고르는 것도 내 결정이므로, 고른 대가는 화면의 기록 줄에 남습니다(ui.md 2절).
- 태그가 생기거나 사라지고, 상처가 오르면 그 표시가 바뀝니다.

### 2.6 굴림이 없는 행동

이동, 살펴보기, 집기, 건네기, 잡담, 공짜 화제, 선택, 장면 넘김에는 주사위가 나오지 않습니다. 결과가 정해진 행동에 주사위를 보이면 주사위가 뜻을 잃기 때문입니다. 갈림의 선택(`choose`)은 위험이 높음이라 확인 카드가 나오지만 주사위는 없습니다.

숨은 막힘이 있으면 굴림 카드를 거쳐 굴렸어도 주사위 대신 막힘이 드러납니다. 주사위는 구르다 멈추지 않고 접시에서 사라지고, 무엇이 막았는지가 뜹니다. 숨은 것은 해 봐야 아는 것이라는 규칙(rule 정리 5)을 그대로 겪게 합니다.

## 3. 한 턴의 흐름

```
문장 또는 버튼
  │
  ├─ 되묻기 카드 ─ 고름 ─┐
  │                       ▼
  ├─ 굴림이 없는 단계들을 실행 ─────────────────────────┐
  │                                                    │
  ├─ 굴리는 단계에 닿음 → (앞 단계들의 서술) → 굴림 카드 │
  │      결정 → 굴림 → 드러남 → 치름 → (대가 카드)      │
  │      → 남은 단계를 이어 실행                        │
  │                                                    ▼
  └──────────────────────────────────────────► 서술 → 다음 명령
```

- 한 문장의 여러 단계("문으로 가서 자물쇠를 연다") 중 굴리는 단계에서 멈춥니다. 그 앞의 단계는 이미 실행되어 한 턴이 되고, 서술이 먼저 나온 뒤 굴림 카드가 열립니다.
- 굴린 단계가 실패하거나 고를 대가가 생기면 멈추고, 아니면 남은 단계를 이어 실행합니다(engine 2.5). 이어진 단계에 굴림이 또 있으면 그 앞에서 다시 카드가 열립니다.
- 서술은 드러남이 끝난 뒤 보입니다. 서술 요청은 굴림 응답을 받자마자 시작해, 드러나는 동안 모델이 씁니다.

## 4. 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 다시 굴리기, 굴림을 사는 것 | 주사위가 가볍게 여겨지고, 실패가 상황을 바꾸지 못함(fun.md 결과) |
| 굴리지 않는 행동의 주사위 연출 | 2.6 |
| 확률을 숨기는 것 | 긴장은 결과의 불확실함에서 오고, 걸린 것을 아는 데서 커짐(fun.md 긴장) |
| 서술이 숫자를 말하는 것 | 숫자는 드러남이 이미 보였음. 서술은 이야기를 씀 |
| 카드에서 방식과 대상을 바꾸는 것 | 2.2 |
| 주사위 값을 미리 증명하는 장치 | 1절. 공정함은 규칙의 적용에서 옴 |

## 5. 엔진에 대한 요구

| | 요구 | 근거 |
|---|---|---|
| X1 | **굴림 카드**: 굴리는 단계마다 실행 직전에 멈추고 카드를 둠. 카드는 행동의 의도 인자를 고정하고, 허용되는 기댈 것과 그것마다의 미리보기를 담음 | 2.1, 2.2 |
| X2 | **미리보기 = 실행**: 카드의 위험과 `z`는 실행 때의 값과 같음 | 2.2, rule.md 3.4 |
| X3 | **카드 = 확인**: 굴림 카드를 수락하는 것이 그 행동의 확인. 위험이 높음인 굴림에 확인 카드를 따로 두지 않음 | 2.1, engine G5 |
| X4 | **단계 기록**: 응답이 실행한 단계마다 행동 이름, 주사위, 보정의 이름과 부호, 결과, 위험, 보이는 변화(칸, 태그, 상처, 시계, 위기, 도착)를 담음 | 2.4, 2.5 |
| X5 | **서술 앞의 응답**: 굴림의 응답은 서술을 기다리지 않음. 서술은 따로 요청해 드러나는 동안 씀 | 2.3, 3절 |
| X6 | **다시 열기**: 다시 연 화면은 마지막 턴의 단계 기록과 기다리는 카드를 그대로 보임. 드러남을 다시 연출하지 않음 | engine 정리 7 |
| X7 | **보이는 것만**: 카드, 미리보기, 단계 기록은 관찰과 그 턴의 기억 투영만 읽음 | 온톨로지 공리 5 |

X1과 X3은 엔진 이론의 턴(engine 2.5)에 카드 하나를 더하는 것입니다. 카드는 사건을 만들지 않고 `t`를 늘리지 않으며(온톨로지 공리 4), 카드에서 고른 기댈 것은 플레이어의 선택이라 선택자입니다(engine 정리 1의 따름). 그래서 엔진 이론의 정리는 그대로이고, 바뀌는 것은 판단 인자 `rely`를 정하는 자리가 결정 모델에서 플레이어로 옮겨 가는 것입니다(engine.md 3.3).

## 6. 시간

| 구간 | 길이 |
|---|---|
| 누름 → 응답 전 구름 | 최소 600ms, 응답이 오면 끝 |
| `d₁`, `d₂` 멈춤 | 각 250ms, 120ms 차이 |
| 합의 점이 떨어짐 | 200ms |
| 보정 칩 하나 | 180ms |
| 결과 찍힘 | 300ms |
| 칸이 참 | 칸 하나에 150ms |

드러남은 보정 칩이 둘이면 2초 안팎입니다. 어디를 눌러도 남은 연출을 건너뛰고 끝 상태로 갑니다. 움직임 줄이기 설정이면 구름과 날아감 없이 각 단계의 끝 상태를 차례로 짧게(100ms씩) 보입니다.

## 7. 재는 것

fun.md 5절의 지표에 둘을 더합니다. 모두 기록과 턴 기록에서 오프라인으로 잽니다.

| | 지표 | 정의 | 처음 가설 |
|---|---|---|---|
| X-F1 | 기대기 | 기댈 것이 있었던 굴림 중 기댄 비율, 그리고 결정적 칩이 기댄 것이었던 비율 | 30~70%, 기록함 |
| X-F2 | 카드 이탈 | 굴림 카드를 닫고 다른 명령을 낸 비율 | 20% 이하 |

X-F1이 너무 낮으면 기댈 것이 보이지 않거나 아깝게 느껴지는 것이고, 너무 높으면 기댈 것이 공짜입니다. X-F2가 높으면 카드가 문장의 뜻과 다른 것을 보이고 있는 것이므로 해석(engine.md 3절)을 먼저 봅니다.
