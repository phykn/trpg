# 엔진 구현

[engine.md](../theory/engine.md)의 문맥, 질문 나무, 받아들이기, 턴, 서술을 코드로 옮기고, [experience.md](experience.md)의 요구 X1~X7을 만족하는 프로토콜과 API를 정합니다. 상태와 관찰은 [ontology.md](ontology.md), `K`와 `R`과 미리보기는 [rule.md](rule.md)의 것을 씁니다. 지금의 코드와 무관하게 이론에서 끌어냈고, 이론이 열어 둔 자리를 정한 것은 11절에 모았습니다.

```
server/src/
  onto/  rules/          ontology.md, rule.md
  story/                 load.py(원고 읽기), validate.py(V1~V6)
  locale/ko.py           틀 표 𝔗, 행동 이름 λ, 공통 문장, 해석 어휘
  lang/                  context.py(ρ), claims.py(κ), polite.py(합니다체)
  models/                kev.py(결정 모델), qwen.py(서술 모델)
  interpret.py           질문 나무와 받아들이기
  cards.py               되묻기, 굴림, 확인 카드
  narrate.py             서술, 검사, 다시 쓰기, 되돌아보기
  view.py                GameView, 단계 기록
  service.py             턴 프로토콜(잠금, revision, 영수증)
  api.py                 HTTP 경계
```

모델을 부르는 곳은 `interpret.py`와 `narrate.py`, 그리고 시작 시의 확인뿐입니다. 두 파일이 받는 것은 `Obs`와 그로부터 만든 글, 외생 입력뿐입니다(G1).

## 1. 틀 표와 이름

`locale/ko.py`의 틀 표 `𝔗`는 술어마다 현재 틀과 변화 틀을 둡니다. 이야기와 무관한 엔진의 어휘입니다(G6).

| 술어 | 현재 틀 | 변화 틀(더해짐 / 빠짐) |
|---|---|---|
| `at(x, 장소)` | {x}은(는) {y}에 있습니다 | {x}이(가) {y}에 왔습니다 / {x}이(가) {y}를 떠났습니다 |
| `at(x, agent)` | {y}이(가) {x}을(를) 지니고 있습니다 | {y}이(가) {x}을(를) 얻었습니다 / {y}이(가) {x}을(를) 내주었습니다 |
| `link(p, q)` | {p}에서 {q}(으)로 갈 수 있습니다 | 길이 열렸습니다 / 길이 끊겼습니다 |
| `mark` | {x}에 {태그 이름}이(가) 있습니다 | 생겼습니다 / 사라졌습니다 |
| `fill` | {o}: {n}/{칸} | {o}이(가) {n}칸이 되었습니다 |
| `regards` | {g}이(가) 당신을 {신뢰·두려움 낱말}합니다 | 마음이 움직였습니다(축과 방향) |
| `stat` | 당신의 {항목}: {n} | {항목}이(가) {n}이(가) 되었습니다 |
| `owes` | 당신은 {h}에게 {약속 이름}을 약속했습니다 / {g}이(가) 당신에게 신세를 졌습니다 | 약속을 지켰습니다 / 어겼습니다 |
| `due`, `spent` | 화면 전용, 문맥에 넣지 않음 | |

조사는 `locale/ko.py`의 받침 함수로 고릅니다. 이름은 원고의 `name`, 태그 이름은 표현층의 이름(6절), 없으면 원고의 기본 이름이나 엔진의 기본 이름("유리함", "불리함")입니다.

**행동 이름** `λ(a)`는 스키마마다 틀 하나입니다: `go` "{q}(으)로 간다", `try` "{x}에 {방식}(으)로 맞선다", 해법이면 원고의 `label`, `talk` "{h}에게 {화제 제목}을 묻는다" 등. 버튼, 되묻기, 결정 모델의 선택지, 단계 기록이 모두 `λ`를 씁니다.

## 2. 문맥 `ρ`

`lang/context.py`의 `context(U, O, X) → list[Line]`은 engine 2.2의 네 갈래를 만듭니다.

1. **사실**: `F`의 원자 중 개체 자리 하나가 초점 `X`에 있는 것마다 현재 틀 한 줄.
2. **믿음**: `B`의 명제 중 `about`이 `X`와 겹치는 것마다 "당신이 믿는 것: {text}". 장소 없는 명제(화제의 `text`, 인물의 믿음)는 그 화제를 가진 인물이 `X`에 있으면 넣습니다.
3. **기억**: `M`의 최근 사건 중 `X`의 개체가 나오는 것을 변화 틀로. 지난 일로 씁니다.
4. **공개 매개변수**: `X`의 개체마다 감각 단서, 말투, 욕망, 두려움, 생김새, 화제 제목. 인물의 `wants`는 그 물건이 플레이어에게 숨지 않았을 때만.

`Line`은 갈래와 원자(사실이면)를 함께 지닙니다. 프롬프트로는 갈래 머리말 아래 글로 나가고, 검사(5.3)는 같은 줄에서 원자를 찾습니다.

| 쓰는 곳 | 초점 |
|---|---|
| 해석 1층 | `{player, here}` |
| 해석 2층 | `{player, here}`와 그 자리의 선택지에 나오는 개체 |
| 서술 | `({player, here}` ∪ `here`의 보이는 인물 ∪ `δ`의 개체`) ∩ E` |

## 3. 해석

`interpret.py`는 문장 하나를 계획(단계의 열), 되묻기, 거절 중 하나로 바꿉니다(engine 정리 2). 질문은 모두 닫혀 있고, `Ω`는 모델을 부르기 전에 계산합니다(G3).

### 3.1 0층: 규칙

모델 없이 정합니다. 확정되면 그 질문은 모델에게 가지 않습니다.

| 규칙 | 결과 |
|---|---|
| 원고의 `impossible` 구절이 들어 있음 | 거절("이 세계에는 없는 것입니다") |
| 게임에 대한 요청(`ko.META`: 저장, 다시 시작, 규칙 질문 등) | 거절과 안내 |
| 문장이 후보의 `λ`나 해법의 `label`과 같음(띄어쓰기와 문장부호 무시) | 그 행동 하나의 계획 |
| 개체의 이름이나 별칭이 나옴 | 2층의 그 자리를 그 개체로 채움(값이 후보 안일 때) |
| `…에게`, `…한테` 앞의 이름 | `give`, `talk`의 상대 |
| 방식 어휘(`ko.APPROACH_WORDS`: "밀어", "몰래", "살펴", "달래" 등) | `try`의 방식 |
| 기댈 것의 이름(지닌 물건, 특성, 태그 이름, 믿는 명제의 핵심어) | `rely`의 기본값(3.3) |

### 3.2 1층: 부분

단계 셋을 한 호출로 묻습니다.

- 1단계: `{σ ∈ Σ_말 | space(σ)가 비지 않음}`, 많아야 9개.
- 2·3단계: `Σ_말 ∪ {끝}`, 10개.

선택지의 설명은 `locale/ko.py`의 스키마 설명입니다("어딘가로 간다", "무언가를 살핀다", "누군가와 말한다", "무언가에 맞서거나 해 본다" …). 0층이 계획을 정했으면 묻지 않습니다.

### 3.3 2층: 자리

단계 `i`를 실행하기 **직전**에, 그때의 관찰로 그 단계의 자리를 묻습니다. 한 단계의 자리들은 한 호출로 묶습니다. 값이 하나뿐인 자리, 0층이 채운 자리는 묻지 않습니다.

| 자리 | 종류 | 묻는 방식 |
|---|---|---|
| 갈 곳, 대상, 물건, 상대, 화제, 잠재, 갈림의 선택지 | 의도 | `space`의 값들을 `λ`나 이름으로 |
| 방식 | 의도 | 넷. `try`의 대상이 정해진 뒤 |
| 무리함 | 판단 | `natural`, `forced`, `불가능`. `불가능`이면 문장 거절 |
| 태도 | 판단 | 다섯 |
| 주장 | 판단 | 태도가 `deceive`일 때만, 원고의 주장 문장들과 "없음" |
| 기댈 것 | 판단 | **묻지 않음.** 0층의 이름 맞추기로만 기본값을 정하고, 굴림 카드에서 플레이어가 고름 |

기댈 것을 묻지 않는 것은 두 가지 이유입니다. 굴림 카드(4.2)가 확률을 보이며 플레이어에게 고르게 하므로 모델이 정할 까닭이 없고, 작은 결정 모델이 가장 약한 것이 세부 자리라 질문 하나를 줄이면 지연과 오류가 함께 줄어듭니다(Q5).

### 3.4 받아들이기 `δ_θ`

engine 2.4를 그대로 따릅니다. `θ`는 설정 값이고 처음은 0.5입니다(Q2, Q3로 정함).

| 질문 | `p(ω₁) ≥ θ` | 아니면 |
|---|---|---|
| 1층 1단계 | 받음 | 두 번째 의견: 서술 모델에게 같은 선택지를 번호로 주고 온도 0으로 하나를 고르게 함. `ω₁`과 같으면 받음. 아니면 단계 전체가 `try(player)` |
| 1층 2·3단계 | 받음 | `끝` |
| 2층 의도 | 받음 | 되묻기 카드 `{ω₁, ω₂, ω₃}` |
| 2층 판단 | 받음 | `ν₀` |

### 3.5 결정 모델 호출

`models/kev.py`의 `decide(state, questions)`는 문맥 글 하나와 닫힌 질문 여럿을 한 번에 보내고 질문마다 선택지 위의 확률을 받습니다. 선택지 밖의 답, 읽을 수 없는 답, 시간 제한을 넘은 답은 모든 선택지의 확률이 0인 답으로 바꿉니다(G3, G8). 결정 모델의 지연은 질문 수에 따라 늘어나므로 한 호출의 질문은 1층에서 3개, 2층에서 그 단계의 묻는 자리 수입니다.

## 4. 카드

카드는 엔진이 플레이어에게 묻고 멈추는 것입니다. 사건을 만들지 않고 `t`를 늘리지 않습니다(온톨로지 공리 4). 기다리는 카드는 표현층에 하나만 있고, 새 문장이나 버튼이 오면 버립니다. 카드의 내용은 `(Vₜ, 계획)`의 함수입니다.

```python
@dataclass(frozen=True)
class Card:
    id: str                 # unique per game
    kind: str               # clarify, roll, confirm
    plan: Plan              # the stopped step (fixed arguments) and the rest
    echo: str               # the player's sentence or the button label
    options: tuple[Option, ...]
    selected: str | None    # default option id (roll card)
```

### 4.1 되묻기

2층 의도 자리를 받지 못했을 때입니다. 선택지는 `{ω₁, ω₂, ω₃}`의 `λ`와 "그만두기"입니다. 답을 받으면 그 자리를 채우고 계획을 이어 갑니다.

### 4.2 굴림 (X1~X3)

계획의 다음 단계 `a`가 굴리는 행동이면 실행 직전에 멈추고 굴림 카드를 둡니다. 굴리는지는 관찰로 정합니다: `try(x ≠ player)`는 늘, `talk`는 화제가 `B`에 없고 `free_when`이 보임에서 거짓이거나 호의 없는 부탁일 때(rule.md 5.1). 보임과 세계의 판정이 같은 것은 story.md V3가 `free_when`의 원자를 보이는 것으로 제한하기 때문입니다. 숨은 막힘만 이 판정과 실행을 다르게 하고, 그때는 카드를 거쳐 막힘이 드러납니다(experience.md 2.6).

| 필드 | 내용 |
|---|---|
| `plan` | `a`의 의도 인자와 `rely`를 뺀 판단 인자를 고정한 단계, 그리고 남은 계획 |
| `options` | `rely`의 허용 값마다, 그리고 "기대지 않음" 하나: 행동 id, 이름, 쓰면 사라지는지, `preview(U, O, a_rely)` |
| `selected` | 0층이 정한 `rely`의 선택지, 없으면 "기대지 않음" |
| `echo` | 문장 또는 버튼 이름, 그리고 2층이 읽은 자리의 이름(대상, 방식, 무리함, 태도) |

수락은 `{card, pick}`이고 `pick`은 `options`의 행동 id 하나입니다. 서비스는 요청의 `revision`이 지금과 같고(7절 2) `card`가 기다리는 카드의 id이며 `pick`이 그 카드의 선택지이고 `admits(U, Vₜ, pick)`일 때만 실행합니다. 이 수락이 그 행동 그대로의 확인이므로, 위험이 높음인 굴림에 확인 카드를 따로 두지 않습니다(G5, X3).

### 4.3 확인

굴리지 않는데 위험이 높음인 단계, 즉 `choose`입니다. 선택지는 "고른다"와 "그만두기"이고 선택의 이름과 효과의 이름을 보입니다.

### 4.4 고를 대가

`due`는 카드가 아니라 상태입니다. `due(player, c)`가 있는 동안 후보는 `pay(c)`와 `try(player)`뿐이고(rule 3.4), 화면은 `pay` 버튼을 대가 카드처럼 보입니다. 상태라서 다시 열어도 그대로입니다.

## 5. 서술

`narrate.py`는 턴 `n`의 서술을 요청이 올 때 만들어 표현층에 캐시합니다(G7). 캐시가 있으면 그대로 돌려줍니다.

### 5.1 입력

| 갈래 | 내용 |
|---|---|
| 시스템 | 역할, 형식 규칙(3~6문장, 합니다체, `당신`, 마지막 문장은 지금 상황, 선택지를 늘어놓지 않음, 감정을 정하지 않음, 숫자를 말하지 않음), 원고의 `style` |
| 문맥 | `ρ(Vₜ₊ₖ, X_N)` |
| 일어난 일 | 단계마다 `λ(aᵢ)`, 결과 이름("대가 있는 성공"), 그리고 `δ`를 변화 틀로 옮긴 줄들 |
| 새 태그 | 이번 턴에 생긴 태그의 기본 이름. 서술 속에서 부를 이름을 마지막 줄 `태그: 이름`으로 적게 함 |
| 앞 서술 | 최근 3턴의 서술(표현층) |
| 플레이어 | 이번 턴의 문장(있으면) |

`δ`는 이번 턴 단계들의 기억 투영 `seen[player]`을 차례 합성한 것입니다(engine 4절). 날것의 `Δ`는 쓰지 않습니다.

### 5.2 생성

서술 모델은 늘 생각하지 않는 모드(`enable_thinking: false`)로 부릅니다. 출력 길이 제한은 500토큰입니다. 서술은 한 화면에 넘김 없이 들어가야 하므로(ui.md 2절) 받아들이는 글은 4문장, 공백 포함 200자 이하입니다. 장 전환이나 결말의 턴은 되돌아보기(5.6)와 함께 보이므로 서술 160자, 되돌아보기 100자 이하입니다. 초안은 플레이어에게 흘려보내지 않고, 검사를 통과한 글만 내보냅니다(5.4).

### 5.3 검사

1. **규칙 검사**: 문장 수와 글자 수(5.2), 합니다체(`lang/polite.py`가 해라체 끝맺음을 고침), `당신` 외의 2인칭, 목록과 선택지 꼴, 숫자, `태그:` 줄의 길이(12자 이하)와 숨은 개체의 이름. 아직 얻지 않은 것을 얻었다고 말함(물건 이름 + 얻음 동사인데 `at(x, player) ∉ F'`), 지닌 것을 넘겼다고 말함.
2. **주장 추출** `κ`: 문장마다 이름과 별칭, 틀 표의 변화·현재 틀의 동사 꼴로 `Σ`의 리터럴을 뽑습니다. 양의 리터럴은 `φ ∈ F'`, 부정 리터럴은 `F'`와 `C`에서 따라 나올 때만 받습니다(온톨로지 7.6).
3. **결정 모델 검사**: 1, 2를 통과한 문장마다 두 질문("이 문장은 사실과 어긋나는가", "사실에 없는 사람, 물건, 길을 지어냈는가")을 문맥 `ρ(Vₜ₊ₖ, X_N)`와 함께 한 호출로 묻습니다. 어느 쪽이든 "예"의 확률이 `θ_N` 이상이면 받지 않습니다. `θ_N`은 설정 값이고 처음은 0.5입니다.

### 5.4 다시 쓰기와 끝맺음

받지 못한 문장이 있으면 그 문장과 이유(규칙 검사의 이름, 어긋난 사실의 줄)를 피드백으로 다시 씁니다. 피드백은 `(Vₜ₊ₖ, δ, 초안)`만 읽습니다(G1). 두 번까지 다시 쓰고, 세 번째도 받지 못하면 받지 못한 문장을 지웁니다. 다 지워지면 `δ`의 변화 줄만 서술로 둡니다. 시도마다 다른 seed를 줍니다.

### 5.5 스트림

`GET /games/{id}/turns/{n}/narration`은 NDJSON입니다.

```
{"type": "stage", "stage": "writing"}      초안을 쓰는 중
{"type": "stage", "stage": "checking"}     검사 중
{"type": "stage", "stage": "rewriting", "attempt": 2}
{"type": "text", "text": "…"}              받아들인 서술 전체
{"type": "done", "tags": [{"slot": 1, "owner": "player", "name": "젖은 발"}]}
{"type": "error", "message": "…"}          모델이 응답하지 않음. 다시 요청하면 처음부터
```

캐시가 있으면 `text`와 `done`만 바로 보냅니다. 글자가 나타나는 연출은 화면이 합니다. 검사 전의 글을 보이지 않으므로 화면은 지어낸 문장을 한 번도 보이지 않습니다.

### 5.6 태그 이름과 되돌아보기

`태그:` 줄의 이름은 `(mark 원자, 만들어진 t)`를 키로 표현층에 둡니다(온톨로지 7.6). 장 전환이나 결말이 일어난 턴은, 서술 뒤에 그 장의 되돌아보기를 같은 방식(5.1의 입력 대신 그 장의 주목할 사건 5개까지를 변화 틀로)으로 쓰고 같은 검사를 거칩니다. `GET /games/{id}/chapters/{k}/recap`이 같은 NDJSON으로 돌려줍니다. 결말의 서술에는 원고의 `frame`을 넣습니다.

## 6. 표현층 `P`

| 필드 | 내용 |
|---|---|
| `revision` | 상태나 기다리는 카드가 바뀐 요청마다 1 오름. 거절과 영수증 재생은 올리지 않음 |
| `turns` | 턴 `n`마다 요청의 종류(문장, 버튼, 카드 답), 문장, 실행한 사건 `t`의 범위 |
| `requests` | 사건 없이 끝난 요청(되묻기, 거절, 카드 버림)의 기록 |
| `card` | 기다리는 카드 하나 또는 없음 |
| `narration` | 턴 `n` → 받아들인 서술, 시도 수, 지운 문장 수 |
| `recap` | 장 `k` → 되돌아보기 |
| `tag_names` | `(원자, t)` → 이름 |
| `receipts` | 요청 id → (본문 해시, 응답) |

`R`, `K`, 조건, 관찰은 `P`를 읽지 않습니다(온톨로지 공리 2). 화면과 서술 입력이 `P`를 읽는 것은 이전 모델 출력과 플레이어 입력, 즉 외생 입력을 읽는 것입니다.

## 7. 턴 프로토콜

`service.py`의 `command(game_id, request_id, revision, body)`:

```
잠금(game_id)
  1. receipts[request_id]가 있고 본문 해시가 같으면 저장된 응답을 돌려줌. 해시가 다르면 거절(409, 지금의 view와 함께)
  2. revision ≠ P.revision이면 거절(409, 지금의 view와 함께)
  3. 본문으로 계획을 만듦
       action   → admits 확인 → 계획 [a]
       card     → 그 카드의 계획에 답을 넣음(수락한 굴림이나 확인은 그 단계를 "수락됨"으로 표시)
       cancel   → 카드를 버림, 사건 없음
       text     → 0층, 1층 → 계획, 되묻기, 거절
     새 문장이나 버튼이면 기다리던 카드를 버림
  4. 단계마다
       2층으로 aᵢ를 정함(되묻기 → 카드를 두고 멈춤, 자리가 비면 멈춤)
       admits(U, Vₜ, aᵢ)가 아니면 멈춤                           (P5)
       굴리는 단계이고 수락되지 않았으면 굴림 카드를 두고 멈춤        (X1)
       굴리지 않는 높음이고 수락되지 않았으면 확인 카드를 두고 멈춤   (G5)
       step = resolve(U, S, h, aᵢ, H(seed, t)), 사건을 덧붙이고 S ← S ⊕ Δ
       결말, 실패, due가 생기면 멈춤
  5. 한 단계라도 실행했으면 턴 n을 늘리고 turns에 기록
  6. 상태나 카드가 바뀌었으면 revision +1, 영수증을 쓰고, S·L·P를 한 번에 저장(ontology.md 7.2)
  7. 응답: kind(turn, card, refused), 턴 번호, 단계 기록(8.3), 지금의 view
```

- 2층 질문은 잠금 안에서 부릅니다. 같은 게임의 요청은 한 줄로 서고, 다른 게임은 막지 않습니다.
- 4의 단계 사이에서 관찰은 매번 다시 계산합니다. 앞 단계가 보이게 한 것이 다음 단계의 자리에 나옵니다(engine 2.3).
- 굴림 카드를 수락한 요청은 모델을 부르지 않고 그 단계를 실행합니다. 남은 단계에 2층 질문이 있으면 그때 부르고, 그 시간은 주사위가 구르는 동안에 듭니다(experience.md 2.3).
- 응답 전에 저장합니다. 응답이 사라지면 화면은 같은 `request_id`와 본문으로 다시 보내고, 1에서 같은 결과를 받습니다.
- 서술은 응답 뒤에 따로 요청합니다(X5). 서술은 상태를 바꾸지 않으므로 잠금 밖에서 만들고, 캐시를 쓸 때만 잠급니다. 같은 턴의 서술 요청이 겹치면 하나만 만들고 나머지는 그 결과를 기다립니다.

## 8. API

모든 경로는 Basic Auth를 거칩니다. 응답의 한국어 문장은 서버가 만들고 화면은 그대로 보입니다.

### 8.1 경로

| 경로 | 본문 | 응답 |
|---|---|---|
| `GET /stories` | | 이야기 목록: id, 제목, 전제, 방식 값들, 특성 후보와 `pick` |
| `POST /games` | `{request_id, story, creation}` | `{game_id, view}`. `game_id`는 `request_id`의 해시라서, 같은 요청을 다시 보내면 이미 만든 파일을 찾아 같은 응답을 줌(본문이 다르면 409) |
| `GET /games/{id}` | | `view` |
| `POST /games/{id}/commands` | `{request_id, revision, text}` / `{…, action}` / `{…, card, pick}` / `{…, card, cancel: true}` | `CommandResult` |
| `GET /games/{id}/turns/{n}/narration` | | NDJSON(5.5) |
| `GET /games/{id}/chapters/{k}/recap` | | NDJSON(5.6) |

오류: 없는 게임 404, 낡은 `revision`과 영수증 불일치 409(지금의 `view`와 함께), 호환되지 않는 저장 409(`view` 없이 `reason: "incompatible"`), 형식 오류 422. 모델이 응답하지 않는 것은 오류가 아니라 읽을 수 없는 답이고(G3, 9절), 서술 모델의 실패는 스트림의 `error`입니다.

### 8.2 `GameView`

모두 `Obs`와 표현층에서 만듭니다(X7).

| 필드 | 내용 |
|---|---|
| `revision`, `chapter` | 장 번호와 제목 |
| `scene` | 장소 이름, 감각 단서, 보이는 인물(이름, 태도 낱말), 물건, 장애물(이름, 칸, 막는 것), 갈 곳 |
| `player` | 방식 넷, 특성(이름, 이번 장에 썼는지), 태그(슬롯, 종류, 수명, 이름), 상처/칸, 박자/`B`, 성장 |
| `clocks` | 지닌 위험 시계, 마감, 활성 위협과 갈림(이름, `fill`, 칸 수, 종류) |
| `journal` | 믿는 것(`B`의 문장, 믿게 된 차례, 지금 장면의 개체를 말하는지), 약속과 신세(`owes`), 인물별 관계, 고른 대가와 갈림의 선택(이름, 장) |
| `buttons` | 추천 `β`: 행동 id, 이름, 굴리는지 |
| `due` | 고를 대가: `pay` 행동 id, 이름, 무게 |
| `growth` | 성장 행동들(성장이 1 이상일 때) |
| `card` | 기다리는 카드 |
| `last` | 마지막 턴의 번호, 단계 기록, 서술이 캐시되었는지 |
| `recaps` | 되돌아보기가 있는 장 번호들 |
| `bands` | 결과 경계 `{"mixed": 7, "success": 10}`와 눈금 `{"min": 1, "max": 16}`. 화면은 그리기에만 씀 |
| `ending` | 결말 id와 제목, 또는 없음 |

### 8.3 단계 기록 (X4)

실행한 단계마다 하나입니다. 사건의 플레이어 투영 `seen[player]`과 `λ`, 표현층의 이름으로 만듭니다.

```json
{
  "t": 7, "action": "try:door:finesse;rely=thing:key", "label": "열쇠로 자물쇠를 연다",
  "result": "mixed", "risk": "normal",
  "roll": {"d1": 4, "d2": 3},
  "mods": [{"kind": "stat", "label": "솜씨", "value": 2},
           {"kind": "help", "label": "등대 열쇠", "value": 1},
           {"kind": "hinder", "label": "흩날리는 물보라", "value": -1}],
  "total": 9, "decisive": [2],
  "changes": [{"kind": "fill", "id": "door", "name": "녹슨 등대 문", "from": 0, "to": 2, "fit": 1},
              {"kind": "clock", "id": "clock.1", "name": "몰려오는 폭풍", "from": 1, "to": 2}]
}
```

- `mods`는 칩의 목록입니다. `stat`, 도움, 방해 차례이고, 방해의 원자가 여럿이어도 방해 하나(값 −1, 이름을 `·`로 이어 씀)입니다(J2).
- `total`과 `decisive`는 서버만 계산합니다. 화면이 규칙을 되풀이하지 않게 하기 위해서입니다. `decisive`는 빼면 결과가 바뀌는 칩의 `mods` 안 번호(0부터)들입니다. 위 예에서 물보라의 −1이 없었다면 10으로 성공이었습니다.
- `changes`는 `δ`의 원자를 화면의 종류(`fill`, `clock`, `crisis`, `tag_add`, `tag_remove`, `wound`, `scar`, `move`, `reveal`, `link`, `regards`, `promise`, `arrival`, `chapter`, `ending`)로 묶은 것이고, `from`, `to`는 보이는 값입니다. `fill`의 `fit`은 그중 어울리는 방식으로 더 찬 칸 수입니다.
- 주사위의 `u`는 보내지 않습니다. 복잡화를 고르는 수일 뿐 플레이어의 경험에 쓰이지 않습니다.

### 8.4 `CommandResult`

```
{ "kind": "turn" | "card" | "refused",
  "turn": 12 | null,          steps가 있으면 그 턴 번호, 없으면 null
  "steps": [단계 기록, …],     실행한 단계(카드로 멈춰도 그 앞의 단계는 있음)
  "reason": "…",                거절의 이유(refused)
  "view": GameView }
```

## 9. 모델과 시작

| | 결정 모델(Kev, `:8081`) | 서술 모델(Qwen, `:8082`) |
|---|---|---|
| 하는 일 | 1층, 2층, 서술 검사 | 서술, 다시 쓰기, 되돌아보기, 두 번째 의견 |
| 시간 제한 | 호출마다 10초 | 서술 60초, 두 번째 의견 10초 |
| 넘으면 | 읽을 수 없는 답(G3) | 그 시도는 실패, 세 시도가 모두 실패하면 스트림 `error` |

서버는 시작할 때 모든 이야기를 story.md V1~V6로 검증하고, 두 모델에 짧은 요청을 보냅니다. 하나라도 실패하면 서지 않습니다. 모델을 켜거나 끄지 않습니다.

## 10. 의무와 검사

| 의무 | 지키는 곳 | 테스트 |
|---|---|---|
| G1 문맥 순수 | `interpret`과 `narrate`가 `Obs`, `λ`, 외생 입력, 원고 상수만 받음 | 숨은 원자만 다른 두 상태 → 같은 프롬프트(가짜 모델이 받은 글을 비교) |
| G2 비밀은 명제로 | story.md V4 | 시작 시 검증 |
| G3 닫힌 질문 | `decide`가 선택지 밖 답을 0으로 | 엉터리 답을 내는 가짜 결정 모델 |
| G4 중립 기본값 | 3.4. 버튼의 판단 인자는 `ν₀`이고, `rely`만 굴림 카드에서 플레이어가 고름(11절) | 모든 판단 자리에 낮은 확신 |
| G5 확인 | 굴림 카드(4.2)와 확인 카드(4.3), 요청의 `revision`과 카드 id | 연쇄 둘째 단계가 높음, 낡은 카드의 수락 |
| G6 한 표 | `ρ`, `λ`, `κ`가 `locale/ko.py`의 `𝔗` 하나를 씀 | `κ(ρ_사실(O, X))`가 그 사실들과 같음 |
| G7 프로토콜 | 7절, 서술 캐시 | 동시 요청, 같은 요청 id, 서버 재시작 뒤 같은 view와 같은 서술 |
| G8 끝맺음 | 9절의 시간 제한, 출력 길이, 시도 수 | 응답하지 않는 가짜 모델, 늘 거절하는 가짜 검사기 |
| X1, X3 | 4.2, 7절 | 굴리는 단계마다 카드가 먼저 나옴, 카드 밖 `pick` 거절 |
| X2 | rule.md 3.4 | 카드의 미리보기와 단계 기록의 `mods` 값의 합(`z`), 위험이 같음 |
| X4, X7 | 8.3이 `seen[player]`에서 만들어짐 | 숨은 변경이 단계 기록에 없음 |
| X5 | 7절, 5.5 | 굴림 수락 요청이 서술 모델을 부르지 않음 |
| X6 | `view.last`, `view.card` | 다시 연 view가 응답의 view와 같음 |

해석의 품질은 정리가 아니라 측정입니다. `scenarios/<id>/evals.yaml`의 문장으로 1층과 2층의 정답률(Q2)을, 실제 플레이의 기록으로 보정(Q3)과 서술 수용(Q1)을 잽니다. 해석 규칙을 고치기 전에 새로 모은 평가 묶음으로 먼저 재고, 고치기 전 수치를 함께 보고합니다.

## 11. 여기서 정한 것

| | 자리 | 정한 것 | 이유 |
|---|---|---|---|
| 1 | 기댈 것을 정하는 자리 | 결정 모델에게 묻지 않고, 0층의 이름 맞추기를 기본값으로 굴림 카드에서 플레이어가 고름 | experience.md 2.2. 플레이어의 선택은 선택자라 engine 정리 1~3이 그대로 성립함 |
| 2 | 굴림 카드 | 굴리는 단계마다 실행 직전에 둠. 높음의 확인을 겸함 | experience.md X1, X3 |
| 3 | 굴리는지의 판정 | 관찰로 함. 숨은 막힘만 다르고 그때는 막힘이 드러남 | 카드는 `Vₜ`의 함수여야 함(공리 5) |
| 4 | 서술의 스트림 | 검사를 통과한 글만 보냄. 글자가 나타나는 연출은 화면이 함 | 지어낸 문장을 보였다가 거두는 일이 없음. 지연은 드러남 연출이 덮음 |
| 5 | 단계 기록의 계산 | 합과 결정적 보정을 서버가 계산 | 화면이 규칙을 되풀이하지 않음 |
| 6 | `θ`, `θ_N`의 처음 값 | 0.5 | 측정(Q2, Q3)으로 고침 |
| 7 | 되돌아보기 | 장 전환이나 결말의 턴에 따로 요청 | 서술 캐시와 같은 방식으로 다시 열 수 있음 |
| 8 | 경로 | `/games/*`를 유지하고, 명령은 `commands` 하나로 받음 | 브라우저에는 `trpg.game_id`만 남음. 옛 저장은 `schema_version`이 달라 409 |

engine 2.5의 "버튼의 판단 자리는 `ν₀`라서 직접 쓰는 문장이 늘 조금 유리하다"는 1로 바뀝니다. 기댈 것은 누구나 카드에서 고르므로, 문장의 이점은 방식, 대상, 태도, 주장을 자유롭게 정할 수 있는 데 남습니다. fun.md H2는 이 차이로 재야 합니다.
