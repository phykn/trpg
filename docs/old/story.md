# 이야기 형식

이야기는 전부 이야기 파일에 있다. 엔진 코드에는 이야기가 한 줄도 없다. 이 문서는 `scenarios/<폴더>/`에 무엇을 어떻게 쓰는지, 서버가 켜질 때 무엇을 검사하는지 정한다.

## 한눈에

- 이야기 하나는 `story.yaml` 파일 하나다. 세계, 문체, 시범 경로가 모두 들어 있다.
- 이야기는 4장의 **효과**로만 세계를 바꾼다. 장 넘기기, 결말, 위험 시계, 기한, 상처는 정해진 칸에 적기만 하고, 움직이는 것은 엔진이다.
- 이야기가 만드는 행동은 **해법**뿐이다. 해법은 이름과 조건이 붙은 시도다.
- 서버는 켜질 때 모든 이야기를 검사한다. 하나라도 틀리면 켜지지 않는다.

```
scenarios/<폴더>/   폴더 이름은 자유. 이야기 id는 story.yaml 안의 id다
  story.yaml    이야기 전체
  evals.yaml    해석 평가 문장 (시험 자료. 이야기의 일부가 아니다)
```

본보기는 둘이다. [scenarios/skeleton/story.yaml](../../scenarios/skeleton/story.yaml)은 가장 작은 이야기다. [scenarios/pass/story.yaml](../../scenarios/pass/story.yaml)은 세 장짜리이고, skeleton에 없는 것(`uses`, `consume`, `forget`, `until`이 붙은 `avoids`, 글이 붙은 깃발)을 쓴다.

## 1. 파일 쓰는 법

- **YAML 1.2의 일부만 쓴다.** 앵커, 별칭(`&`, `*`), 태그(`!`)는 못 쓴다. 값은 형식이 정한 자료형으로만 읽는다(`no`, `on`은 글자다). 주석은 한국어로 쓴다.
- **적은 순서가 뜻을 가진다.** 연쇄, 결말, 사고는 파일에 적힌 순서대로 본다.
- **id는 맵의 키다.** `id` 칸을 따로 두지 않는다. 장소, 사람, 물건, 장애물, 위협, 갈림길, 해법, 사고, 화제, 믿는 사실, 거짓말, 숨은 사연, 선택지, 연쇄, 결말, 특성이 모두 그렇다.
- id는 영어 소문자, 숫자, `_`만 쓰고 이야기 전체에서 겹치지 않는다.
- 못 쓰는 id: `player`, `chat`, `favor`, `come`, `stay`, `pass`, `rest`, `chapter`, `ending`, `promise`, `kindness`, `full`, `fired_`로 시작하는 것. `collapse`는 결말에만 쓴다.
- 장소, 사람, 물건, 장애물, 위협, 갈림길에는 `name`이 꼭 있다. `aliases`(다른 이름)는 없어도 된다. 다른 이름은 이야기 어디에서도 서로 겹치지 않는다. 엔진은 이 이름으로 사실과 변화를 글로 쓰고 읽는다(engine.md의 해석).
- **숨길 것은 사실 문장(5장)에만 쓴다.** 나머지 글은 모두 공개다: `premise`, `style`, 이름과 다른 이름, `senses`, `look`, `voice`, `desire`, `fear`, `knows`, 특성의 `text`, 화제의 `title`, `label`, 사고·선택지·기본 선택·약속·숨은 사연·위험 시계·기한의 `name`, 거짓말의 `text`, 결말의 `title`과 `frame`.

## 2. 공통 값

| 종류 | 쓸 수 있는 값 |
|---|---|
| 방법 | `force` 완력, `finesse` 솜씨, `wits` 재치, `charm` 매력 |
| 위험 | `low` 낮음, `normal` 보통. 높음(`high`)은 규칙이 올려서만 나온다 |
| 말투 | `polite` 공손, `threaten` 위협, `deceive` 속임 |
| 무리 | `natural` 평소대로, `forced` 무리해서 |
| 마음 | `trust` 신뢰, `fear` 두려움 |
| 태그 | `edge` 좋은 태그, `snag` 나쁜 태그 |
| 수명 | `scene` 장면, `chapter` 장. `wound`는 엔진의 상처만 쓴다 |
| 사고 무게 | `light` 작은 사고, `heavy` 큰 사고 |
| 결과 | `success` 성공, `fail` 실패, `none` 굴리지 않고 됨, `blocked` 막힘. `mixed`는 없다 |

## 3. 조건

조건은 키가 하나인 맵이다.

| 쓰는 법 | 뜻 |
|---|---|
| `{at: [x, y]}` | `x`가 `y`에 있다 (`y`가 사람이나 `player`면 갖고 있다) |
| `{link: [p, q]}` | 장소 `p`에서 `q`로 길이 있다 |
| `{believes: [g, p]}` | `g`가 사실 `p`를 믿는다. `p`는 사실 id(5장) |
| `{fill: [o, 비교, n]}` | `o`의 찬 칸 수를 `n`과 비교한다. `n` 자리에 `full`(칸 수 전체)을 쓸 수 있다 |
| `{regards: [g, h, 마음, 비교, n]}` | `g`가 `h`에게 품은 신뢰나 두려움을 `n`과 비교한다 |
| `{mark: [x, 태그]}` | `x`에 그 태그가 붙어 있다 |
| `{owes: [g, h, k]}` | `g`가 `h`에게 빚이 있다. `k`는 `promise`(부탁의 약속) 또는 `kindness`(신세) |
| `{flag: [이름, 값]}` | 깃발가 그 값이다. 이름은 `flags`에 적은 것이거나 `chapter`(장 번호) |
| `{did: [행동 id 앞부분]}`, `{did: [행동 id 앞부분, 결과]}` | 그런 행동을 한 적이 있다 |
| `{all: [...]}`, `{any: [...]}`, `{not: c}` | 모두, 하나라도, 아니다. `{all: []}`는 참, `{any: []}`는 거짓 |

비교는 `=`, `>=`, `<=`, `>`, `<`다.

**`did`가 맞는 때**

- 행동 id가 적어 둔 앞부분으로 시작한다. `:`로 나눈 조각 단위로 견준다.
- 앞부분에 `;키=값`을 적었으면 그것이 모두 같다.
- 결과를 적었으면 결과도 같다.

**조건을 무엇으로 따지는가.** 조건이 놓인 자리가 정한다. 6장 표의 "따지는 곳"에 적혀 있다.

- **보이는 것**: 플레이어가 아는 사실과 플레이어가 본 기록, 그리고 이야기에 고정된 값.
- **세계**: 실제 세계 전체와 모든 기록(ontology.md의 세계 상태).

## 4. 효과

효과는 연산을 차례로 적은 목록이다. 앞 연산이 바꾼 세계를 뒤 연산이 본다. 이야기가 쓸 수 있는 연산은 이것뿐이다.

| 쓰는 법 | 하는 일 | 대상 |
|---|---|---|
| `{move: [x, y]}` | `x`를 `y`로 옮긴다 | `x`는 물건, 사람, `player`. `player`면 `y`는 장소 |
| `{set: [fill, o, v]}` | 찬 칸 수를 바꾼다 | 장애물, 위협, 갈림길 |
| `{set: [regards, g, h, 마음, v]}` | 신뢰나 두려움을 바꾼다 | `g`는 사람, `h`는 `player`만 |
| `{set: [flag, 이름, v]}` | 깃발 값을 바꾼다 | `flags`에 적은 깃발와 그 값만 |
| `{reveal: [g, p]}` | `g`가 사실 `p`를 믿게 된다 | 사실 |
| `{forget: [g, p]}` | `g`가 사실 `p`를 더는 믿지 않는다 | 사람이 믿는 사실. 플레이어는 안 된다 |
| `{consume: [x]}` | 물건이 세계에서 사라진다 | 물건 |
| `{tag: [x, 태그, 수명, 기본 이름]}` | 태그를 붙인다 | 수명은 `scene` 또는 `chapter` |
| `{link: [p, q]}`, `{unlink: [p, q]}` | 길을 잇는다, 끊는다 | 장소 |
| `{retire: o}` | 치운다 | 장애물, 위협, 갈림길 |

- `v`는 값이다. 숫자 값은 `"+n"`, `"-n"`으로 써서 지금 값에 더하거나 뺄 수 있다. 한계에서 멈춘다. 위협의 지금 값을 몰라도 한 칸 늦출 수 있다.
- 태그의 기본 이름은 서술이 이름을 붙이기 전까지 쓰인다. 나쁜 태그는 무엇이 잘못되는지, 좋은 태그는 무엇이 돕는지를 이름으로 쓴다.
- `forget`은 사람을 설득하거나 거짓말이 먹혔을 때 쓴다. 그 행동의 `did`를 조건으로 한 연쇄에 건다.

**이야기 효과로 못 하는 것**

- 시간 한 칸과 능력치는 못 바꾼다. 규칙만 바꾼다.
- 상처는 사고의 `wound`로만 준다.
- 위험 시계와 기한은 id가 없어서 가리킬 수 없다.
- 위협과 갈림길은 `move`로 옮길 수 없다.
- `chapter`, `ending`, `fired_` 깃발는 `set`할 수 없다.

## 5. 사실

사실을 모아 적는 칸은 없다. 쓰이는 자리에 문장 하나로 적으면 사실이 된다. 이야기의 사실은 참·거짓이 바뀌지 않는다.

| 적는 자리 | 사실 id | 참인가 | 누가 믿게 되는가 |
|---|---|---|---|
| 무엇의 `hidden` | `x.hidden` | 참 | 그것을 `reveals`하는 화제를 연 플레이어. 또는 숨어서 막던 것이 드러날 때 |
| 무엇의 `clue` | `x.clue` | 참 | `x`를 살펴본 플레이어 |
| 화제의 `text` | 화제 id | 참 | 그 화제를 연 플레이어 |
| 사람의 `beliefs` | 믿는 사실 id | 참 | 그 사람(처음부터) |
| 거짓말 | 거짓말 id | 거짓 | 아무도. 들키는지 따질 때만 쓴다 |
| 숨은 사연의 `text` | 숨은 사연 id | 참 | 선언한 플레이어 |

- `hidden`이 있는 것은 **숨어 있다.** 플레이어가 `x.hidden`을 믿게 되면 보인다.
- `clue`는 숨기지 않는다. 살펴보면 알게 되는 것이다.
- 숨은 사연의 사실은 `brings`로 데려오는 것들에 대한 사실이고, 그것들을 보이게 한다.

## 6. 항목

### 6.1 맨 위

| 키 | 내용 |
|---|---|
| `id` | 이야기 id. 폴더 이름과 상관없고 이야기끼리 겹치지 않는다 |
| `version` | 정수. 저장에 적힌다. 저장이 맞는지는 파일 지문으로 본다(ontology.md의 저장) |
| `title`, `premise` | 제목, 공개 전제 |
| `beats` | 장면 길이. 시간 몇 칸이면 장면이 끝나는가. 2 이상 |
| `flags` | 이야기 깃발 (아래) |
| `style` | 문체. 서술 모델에 그대로 넘긴다(여러 줄) |
| `impossible` | 이 세계에 없는 것을 가리키는 말들(engine.md의 해석) |
| `player` | 6.2 |
| `places`, `characters`, `things`, `obstacles` | 6.3~6.6 |
| `chapters`, `threats`, `forks` | 6.7~6.8 |
| `claims`, `latents`, `triggers`, `endings` | 6.9~6.11 |
| `witnesses` | 9장 |

**깃발** `flags`

- `{이름: [값, …]}` 또는 `{이름: {값: 글, …}}`로 쓴다.
- 첫 값이 시작 값이다. 값은 이어진 정수이거나 글자다.
- **글이 붙은 깃발는 공개다.** 글이 붙은 값인 동안 그 글이 서술에 사실 한 줄로 늘 들어가고, 값이 바뀌면 변화 한 줄로 들어간다. 날씨, 빛, 장소의 상태처럼 서술이 앞질러 말하면 안 되는 것에 쓴다. 보이는 것으로 따지는 조건에서도 읽을 수 있다.
- 게임은 `chapter`가 1이고 깃발가 시작 값인 채로 시작한다.

**없어도 되는 칸.** 아래 말고는 모두 꼭 써야 한다.

- 맨 위: `flags`, `impossible`, `threats`, `forks`, `claims`, `latents`, `triggers`
- 어느 항목이든: `aliases`, `clue`, `hidden`, `complications`
- 주인공: `traits`
- 장소: `rest`
- 사람: `regards`, `beliefs`, `wants`, `topics`, `favor`, `avoids`
- 화제: `free_when`(없으면 거짓)
- 장애물: `risk`(없으면 `normal`), `fits`, `clashes`, `blocks`
- 해법: `rely`, `when`
- 장: `goal`(마지막 장에만 없다), `goal_effects`, 기한의 `effects`와 `ending`
- 숨은 사연: `brings`, `effects`
- 파일 `evals.yaml`

### 6.2 주인공 `player`

| 칸 | 뜻 |
|---|---|
| `start` | 시작 장소 |
| `approaches` | 숫자 넷. 예: `[2, 1, 1, 0]`. 각각 0~3. 플레이어가 이 합을 네 능력치에 나눠 준다. 어느 능력치도 여기서 가장 큰 수를 넘지 못한다 |
| `traits` | `{pick: n, options: {id: {name, text}}}`. `n`은 1 이상이고 선택지는 `n`보다 많다 |

- 특성은 주인공의 배경(직업, 인연, 아는 것)으로 쓴다. 능력치와 겹치지 않게 한다.
- 처음 가진 물건은 `things`에서 `at: player`인 것이다.
- 시간과 성장은 0에서, 상처 없이 시작한다.

### 6.3 장소 `places`

| 칸 | 뜻 |
|---|---|
| `name`, `aliases` | 이름, 다른 이름 |
| `senses` | 보이고 들리고 느껴지는 것 3~5개 |
| `exits` | 여기서 갈 수 있는 장소들. 하나마다 길 하나 |
| `rest` | 쉴 수 있는 곳이다(`cut:rest`) |
| `clue`, `hidden`, `complications` | 5장, 6.6 |

### 6.4 사람 `characters`

| 칸 | 뜻 |
|---|---|
| `name`, `aliases`, `pronoun`, `desire`, `fear` | 공개 글 |
| `voice` | 말버릇 한 줄. 끝에 그 사람다운 대사 한 줄을 `예: "…"`로 붙인다. 서술 모델이 이 예에 말투를 맞춘다. 숨길 것을 넣지 않는다 |
| `persona` | 성격. MBTI 16가지 중 하나(`ISTJ` … `ENTJ`). 그 성격 설명이 서술에 함께 들어간다. 꼭 쓴다 |
| `at` | 시작 장소. 처음에 무대 밖인 사람은 숨은 사연이 데려온다(6.10) |
| `avoids` | 같이 다녀도 들어가지 않는 곳(rule.md의 물건과 동행). 장소 하나, 또는 `{place, until}`. `until`이 참이 되면 그만 꺼린다. 없으면 어디든 따라온다 |
| `regards` | 플레이어에 대한 시작 값 `{trust, fear}`. −3~3. 없으면 0 |
| `beliefs` | 처음부터 믿는 사실. `{id: 문장}` 또는 `{id: {title, text}}` |
| `knows` | 누가 물어도 알려 주는 일상 지식. 4문장까지 |
| `wants` | 건네면 반기는 물건들(rule.md의 물건과 동행) |
| `topics` | 화제. `{id: {title, text 또는 reveals, free_when}}` |
| `favor` | 부탁. `{label, effects, promise: {name, keep, break}}` |
| `clue`, `hidden`, `complications` | 5장, 6.6 |

- **`avoids`**: `fear`와 맞추면 사람이 살아난다. `until`은 보이는 것으로 따지고, 그 사람에게 붙은 조건이다. 꺼리는 곳에서 시작하게 두지 않는다. `until`이 없으면 `move`로도 거기 넣지 않는다.
- **`beliefs`**: 비공개다. 거짓말이 들키는지 따지는 근거이고, 사람이 말해 주지 않는다. 플레이어가 함께 알게 될 수 있는 사실에는 `title`을 붙인다. 화면의 칩과 일지가 그 짧은 이름을 쓴다.
- **`knows`**: 공개다. 숨길 것을 쓰지 않는다. 다른 사람 이름도 쓰지 않는다. 신뢰나 굴림이 들어야 할 지식은 화제로 쓴다.
- **`wants`**: 그 물건이 플레이어에게 숨어 있지 않을 때만 화면과 프롬프트에 나온다.
- **`topics`**: `text`는 화제를 열면 알게 되는 사실이다. `reveals: x`는 `x.hidden`을 알려 준다. `free_when`은 보이는 것으로 따지고, 참이면 굴리지 않고 알려 준다.
- **`favor`**: 사람마다 하나까지. 들어주고 나면 다시 고를 수 없다. `keep`(지킴)과 `break`(어김)는 세계로 따진다. `break`가 없으면 거짓이다. 지키지도 어기지도 않은 약속은 장이 바뀌어도 결말이 나도 빚으로 남는다(rule.md의 약속). 약속에 날짜를 두려면 `name`과 `break`에 쓴다.

### 6.5 물건 `things`

`{name, aliases, look, at, uses, clue, hidden}`

- `at`은 장소, 사람, `player` 중 하나다.
- `uses: n`이면 기댈 때 장마다 한 번이 아니라 모두 `n`번 쓸 수 있다. 마지막에 쓰면 사라진다(rule.md의 기대기).

### 6.6 장애물, 해법, 사고

**장애물** `obstacles`

| 칸 | 뜻 |
|---|---|
| `name`, `aliases`, `look`, `at` | 공개 이름, 생김새(적힌 글자도 여기에), 있는 장소 |
| `risk` | 기본 위험. `low` 또는 `normal` |
| `fits`, `clashes` | 잘 맞는 방법(위험 한 단계 아래), 안 맞는 방법(한 단계 위) |
| `blocks` | 막는 장소, 물건, 사람, 장애물 |
| `solutions` | 해법. `{id: {label, approach, rely, when}}`. 둘 이상이고 방법이 서로 다르다 |
| `clue`, `hidden`, `complications` | 5장, 아래 |

- **장애물은 칸이 하나다.** `boxes`를 쓰지 않는다. 한 번 성공하면 넘고, 실패하면 그 방법이 닫힌다. 닫힌 방법은 무리해서만 다시 쓰고, 그때 위험이 한 단계 오른다(rule.md의 장애물).
- 넘었을 때 생기는 일은 연쇄로 쓴다: `{when: {fill: [o, "=", full]}}`.
- **여러 번 굴려야 하는 벽은 장애물을 줄지어 쓴다.** 앞의 것이 뒤의 것을 막는다. 하나하나가 이름과 해법이 따로 있는 다른 상황이다.

> 빗장 걸린 문, 그 뒤의 보초. 문을 열면 이제 보초를 마주한다.

**해법**

- 해법은 "이 장애물에 이 방법으로 시도"에 이름(`label`)과 조건(`when`)을 붙인 것이다. `when`은 보이는 것으로 따진다.
- `rely`는 기대는 것이다. 물건 id나 사실 id를 쓴다. 그 물건을 갖고 있거나 그 사실을 믿어야 한다는 조건이 `when`에 저절로 더해진다.
- 결과, 위험, 대가는 그냥 시도와 같다. 해법으로 적지 않은 방법도 시도할 수 있다. 해법은 할 수 있는 행동을 늘리지 않고 이름만 붙인다.

**막기**

- `blocks`는 장애물이 그 자리에 있고 아직 넘지 않은 동안 듣는다.
- 장소는 가기를, 물건은 집기를, 사람은 말하기를, 장애물은 시도를 막는다.
- 보이는 장애물이 막은 행동은 아예 할 수 없다.
- 숨은 장애물이 막고 있으면, 해 보는 순간 플레이어가 `o.hidden`을 알게 되어 장애물이 드러난다. 시간 한 칸을 쓰고 굴리지 않는다.

**사고** `complications`

`{id: {name, weight, when, effects, wound}}`

- 장소, 사람, 장애물에 붙인다. 붙은 곳이 숨은 조건이 된다: 장소면 거기 있을 때, 사람이면 마주하고 있을 때, 장애물이면 그것에 굴렸을 때.
- `when`은 굴림에 실패했을 때 세계로 따진다(rule.md의 실패하면).
- `wound: n`은 상처 `n`개를 준다. 이야기가 상처를 주는 길은 이것뿐이다.

### 6.7 장 `chapters`

목록으로 쓴다. 적은 순서가 장 번호다(1부터). 장은 언제나 바로 다음 장으로 넘어간다.

| 칸 | 뜻 |
|---|---|
| `title` | 공개 제목 |
| `aim` | 화면에 늘 보이는 목표 한 문장. `goal`을 플레이어의 말로 쓴 것 |
| `goal` | 장의 목표 조건. 세계로 따진다. 마지막 장에는 없다 |
| `goal_effects` | 목표를 이뤄 장이 넘어갈 때 더해지는 효과 |
| `clock` | 위험 시계 `{name, boxes, crisis}`. 꼭 쓴다. `boxes`는 3 이상. `crisis`는 가득 찰 때마다 생기는 효과(하나 이상) |
| `deadline` | 기한 `{name, boxes}`. 꼭 쓴다. `boxes`는 1~6. `effects`와 `ending`을 더 쓸 수 있다 |

- 마지막 장의 기한에는 `ending`이 꼭 있다. `collapse`가 아닌 결말 id를 쓴다. `when`이 있는 결말이어도 된다.

엔진이 알아서 하는 일:

- `k`장에서 `goal`이 참이 되면 `k+1`장으로 넘기고 `goal_effects`를 적용한다.
- 기한이 가득 차면 `effects`를 적용한 뒤, `ending`이 있으면 그 결말을 내고 없으면 다음 장으로 넘긴다. 이렇게 넘어간 장의 기한은 한 칸 찬 채로 시작한다(rule.md의 장이 바뀌면).
- 위험 시계와 기한은 모두 0칸에서 시작한다. 첫 장의 것은 처음부터 나와 있고, 나머지는 그 장이 되면 나온다.

### 6.8 위협과 갈림길

| 칸 | 위협 `threats` | 갈림길 `forks` |
|---|---|---|
| `name` | 공개 이름 | 같다 |
| `boxes` | 칸 수. 1~6 | 같다 |
| `appears_when` | 나타나는 조건. 세계로 따진다 | 같다 |
| `arrival` | 닥쳤을 때의 효과 | 없다 |
| `choices` | 없다 | 선택지 `{id: {name, effects}}`. 둘 이상 |
| `default` | 없다 | `{name, effects}`. 고르기 전에 칸이 다 차면 이렇게 된다. 플레이어가 고를 수는 없다 |

어떻게 움직이는가:

- 처음에는 무대 밖에 0칸으로 있다. `appears_when`이 참이 되면 한 번 나타난다. 특정 장에 묶으려면 조건에 `{flag: [chapter, k]}`를 넣는다.
- 한 번 나타나면 장이 바뀌어도 남는다. 장면이 끝날 때마다 한 칸 찬다(rule.md의 다가오는 것들).
- 가득 차면 `arrival`이나 `default`가 적용되고 치워진다.
- 위협을 물리치려면 다른 효과에서 `retire`한다. `set`으로 칸을 줄이면 늦춰진다.
- 나타나기 전에 `retire`하면 영영 나타나지 않는다.

쓸 때 지킬 것:

- **두고 떠나는 위협은 치운다.** 위협이 어떤 장소의 것이고 다음 장에서 그곳을 떠난다면, 다음 장 깃발에 건 연쇄로 치운다: `when: {flag: [chapter, k]}`, `effects: [{retire: <id>}]`.
- **갈림길은 사람이 묻게 한다.** 그 전에 만날 수 있는 사람이, 장의 목표를 포기해야 얻는 쪽을 바라게 한다(`desire`에 적는다). 연쇄로 그 사람을 갈림길의 장소에 데려오고, 왜 바라는지 말해 주는 `beliefs` 하나를 `reveal`한다. `appears_when`에는 `{at: [<사람>, <장소>]}`를 넣는다. 그러면 선택이 묻는 사람과 이유를 달고 온다.

### 6.9 거짓말 `claims`

`{id: {text, against}}`

- `text`: 플레이어가 하는 말. 공개다.
- `against`: 이 거짓말을 들통내는 사실의 id. 듣는 사람이 그 사실을 믿고 있으면 들킨다(rule.md의 말하기).

### 6.10 숨은 사연 `latents`

`{id: {name, when, text, brings, effects}}`

| 칸 | 뜻 |
|---|---|
| `name` | "분류: 짧은 말" 꼴 |
| `when` | 선언할 수 있는 조건. 보이는 것으로 따진다 |
| `text` | 선언하면 플레이어가 믿게 되는 사실(5장) |
| `brings` | 이 사연에만 딸린 사람과 물건. `characters`, `things`처럼 쓰되 `at`이 없다 |
| `effects` | 선언의 효과. `brings`의 것들을 무대에 올린다 |

**울타리 규칙**

- 숨은 사연의 id와 `brings` 안의 id는 그 사연 밖에서 쓸 수 없다.
- 숨은 사연의 `effects`는 `brings`의 것들만 건드린다: `move`, `tag`, 그 사람들의 `regards`.
- 그래서 선언하지 않은 사연은 세계에 아무 흔적도 남기지 않는다.

### 6.11 연쇄와 결말

**연쇄** `triggers: {id: {when, effects, repeat}}`

- `when`은 세계로 따진다.
- 게임마다 한 번만 일어난다. `repeat: true`면 여러 번 일어난다.

**결말** `endings: {id: {title, when, frame}}`

- `when`이 있으면 그 조건이 참일 때 결말이 난다.
- `when`이 없으면 어느 장의 기한이 `ending`으로 가리켜야 한다.
- `frame`은 결말 서술에 넘기는 공개 문장이다.
- `collapse`(주인공이 쓰러지는 결말, rule.md의 주인공)는 꼭 있어야 한다. `title`과 `frame`만 쓰고 `when`은 없다.

**보는 순서.** 이야기의 연쇄를 이 순서로 본다. 같은 종류 안에서는 적은 순서다. 엔진의 다섯 연쇄는 그 뒤다(rule.md의 연쇄).

1. 위협과 갈림길의 등장
2. `triggers`
3. 장의 목표
4. `when`이 있는 결말

## 7. 행동 id

시범 경로, 버튼, 요청 영수증, `did`가 쓰는 행동 id는 `행동:대상`이다. 어떻게 하는지는 뒤에 `;키=값`으로 붙인다. 붙이지 않으면 기본값이다(공손하게, 평소대로, 기대지 않고).

```
go:village   look:door   take:oil   give:letter:dohae   declare:l_baek   cut:pass   cut:rest
talk:dohae:t_oil;tone=threaten   talk:dohae:favor   talk:dohae:chat;tone=deceive;claim=c_keeper
try:door:finesse;rely=thing:key   try:door:force;strain=forced   choose:g_oil:beacon   grow:finesse
```

`rely` 값에는 무엇에 기대는지 앞에 붙인다(rule.md의 기대기).

| 앞 | 기대는 것 |
|---|---|
| `thing:<id>` | 물건 |
| `prop:<id>` | 아는 사실 |
| `trait:<id>` | 특성 |
| `bond:<id>` | 깊이 믿는 사람 |
| `with:<id>` | 같이 다니는 사람 |
| `tag:<대상>:<자리>` | 좋은 태그 |

해법의 `rely` 칸에는 id만 쓴다. 물건인지 사실인지는 엔진이 이야기에서 찾는다.

## 8. 검사

서버는 켜질 때 모든 이야기를 아래 순서로 검사한다. 하나라도 틀리면 켜지지 않는다. 오류는 영어이고, 틀린 항목의 id와 칸을 알려 준다.

**V1 형식**

- 칸, 자료형, 값의 범위가 맞다.
- id가 겹치지 않고, 가리킨 id가 있다.
- `brings`의 울타리 규칙을 지킨다(6.10).
- 장애물마다 해법이 둘 이상이고 방법이 서로 다르다.
- 장마다 `clock`과 `deadline`이 있다.
- 마지막 장에는 `goal`이 없고, 기한에 `ending`이 있다.
- `when`이 없는 결말은(`collapse` 빼고) 어느 기한이 가리킨다.
- `collapse` 결말이 있다.
- 깃발에는 적어 둔 값만 넣는다.
- 이야기의 사고는 무게마다 58개까지다(엔진이 둘을 더해 60개 중에서 뽑는다).

**V2 시작 상태**

- 시작 상태를 만들 수 있고, 세계가 늘 지켜야 하는 것을 지킨다(ontology.md의 불변 조건).
- 주인공이 정확히 한 장소에 있다.

**V3 놓인 자리**

- 시작하자마자 참인 연쇄 조건이 없다. 엔진의 연쇄도 포함한다.
- 보이는 것으로 따지는 조건(해법과 숨은 사연의 `when`, 사고를 고를 때의 `when`, 화제의 `free_when`, `avoids`의 `until`)은 플레이어가 반드시 아는 것만 읽는다.
  - 플레이어 자신의 것: `at: [player, 장소]`, `at: [물건, player]`, `believes: [player, p]`, `mark: [player, 태그]`, `player`가 낀 `regards`와 `owes`
  - `did`
  - 글이 붙은 깃발
  - 조건이 붙은 그것의 것: `at: [그것, ·]`, `mark: [그것, ·]`, `fill: [그 장애물, ·]`, 사람이면 `believes: [그 사람, ·]`
  - 안 되는 것: 사람이 가진 물건의 `at`, 다른 곳에 있는 것, 글이 없는 깃발
- 막는 장애물은 막는 물건, 사람, 장애물과 같은 장소에 있다.
- 장소를 막는 장애물은 그 장소로 가는 `exits`나 `link` 효과가 있는 모든 장소에 있다.
- 장의 목표 장소는 그 장이 시작하는 곳에서 `exits`만 따라가면 닿는다(막힌 길도 센다). `link` 효과로만 열리는 길이 유일한 길이면 안 된다.
- 사람이 꺼리는 곳에서 시작하지 않고, 이야기 효과가 그곳으로 옮기지도 않는다(`until`이 있는 곳으로 옮기는 `move`는 된다).

**V4 이름**

- 숨은 것(`hidden`이 있거나 `brings` 안에 있는 것)의 이름과 다른 이름이 공개 글(1장)에 나오지 않는다. 이름이 새는 것만 잡는다. 뜻이 새는 것은 쓰는 사람이 챙긴다.
- 다른 이름이 서로 겹치지 않는다.
- 사람의 `knows`에 다른 사람 이름이 없다.
- `impossible`의 말이 이름, 다른 이름, 해법의 `label` 안에 들어 있지 않다.

**V5 시범 경로**: 9장대로 다시 돌려 본다.

**V6 마구 돌리기**

- 할 수 있는 행동 중에서 아무거나 고르고 주사위도 아무렇게나 굴려 결말까지 간다.
- 걸음마다 세계가 늘 지켜야 하는 것을 지키고, 할 수 있는 행동이 하나 이상 있다.
- 굴리는 걸음마다 카드에 보인 위험, 더하고 빼는 것의 목록, 합이 실제로 굴린 값과 같다.

**경고(멈추지 않는다)**: 어느 장의 `beats × 기한 칸 수`가 20보다 작으면 알린다. 장이 재미 지표가 바라는 길이를 담지 못한다(fun.md의 장 길이 지표).

## 9. 시범 경로 `witnesses`

쓰는 사람이 "이렇게 하면 닿는다"를 직접 적어 둔다. 검사가 그대로 돌려 보고, 실패하면 어느 경로의 몇째 걸음인지 알려 준다.

꼭 있어야 하는 경로는 목표마다 하나다.

- 각 장의 목표
- `when`이 있는 각 결말
- `collapse`

더 적어도 된다. 적은 것은 모두 돌려 본다.

```yaml
witnesses:
  creation: {approaches: {force: 1, finesse: 2, wits: 1, charm: 0}, traits: [sailor, tinker]}
  paths:
    - reach: {goal: 1}
      steps:
        - go:village
        - {do: "try:door:finesse", roll: [6, 6, 0]}   # 굴리는 행동에만 주사위를 적는다
    - reach: {ending: two_lights}
      after: 0                                       # 0번 경로의 걸음 뒤에 잇는다
      steps: [choose:g_oil:beacon]
```

- `creation`: 주인공 만들기. 모든 경로가 쓴다. 경로에 따로 적으면 그것이 먼저다.
- `reach`: 닿을 곳. `{goal: 장 번호}` 또는 `{ending: 결말 id}`.
- `after: i`: `i`번 경로의 걸음을 앞에 붙인다.
- `roll`: `[주사위 1, 주사위 2, 사고 뽑는 값]`. `[6, 6, 0]`이면 무엇이든 성공한다.

돌려 보는 법:

- `creation`으로 만든 시작 상태에서 출발한다.
- 걸음마다 그 행동이 지금 할 수 있는 행동인지 보고, 적힌 주사위로 처리한다.
- 마지막 걸음에서 그 장의 목표가 이뤄지거나 그 결말이 나야 한다.
- 기한이 다 돼서 장이 넘어간 것은 목표를 이룬 것이 아니다. 닿기 전에 결말이 나면 실패다.
- 카드와 되묻기는 해석의 일이라 여기에는 없다.

## 10. 해석 평가 `evals.yaml`

진짜 모델로 해석이 맞는지 재는 시험 자료다. 켤 때 하는 검사에는 들어가지 않는다. 사례의 목록이다.

| 칸 | 뜻 |
|---|---|
| `at` | 어느 상태인가. 시범 경로 `path`의 앞 `step`걸음을 한 뒤. 시범 경로가 지나지 않는 상태는 `then`에 행동을 더 적는다(걸음과 같은 꼴: `then: [{do: "talk:h:come", roll: [6, 6, 0]}]`) |
| `text` | 플레이어의 문장 |
| `expect` | 바라는 결과 (아래) |
| `relies` | 없어도 된다. 문장의 첫 굴림 카드가 내놓는 기댈 것들. 카드 순서대로, "기대지 않음"은 빼고 쓴다(engine.md의 카드) |
| `known` | 없어도 된다. 알고 있는 실패라는 표시. 값에 이유를 쓴다 |

`expect`에 쓸 수 있는 것:

- 행동 id 하나: 첫 걸음이 이것이다. 문장이 기댈 것을 말했으면 id에 넣는다.
- 행동 id 목록: 앞 걸음들이 이것이다.
- 행동 종류 이름: 첫 걸음이 그 종류다.
- `refused`: 거절한다.
- `clarify`: 되묻는 카드가 나온다(engine.md의 카드).
- `idle`: 문장 전체를 알아듣지 못했다(engine.md의 해석).

```yaml
- at: {path: 0, step: 2}
  text: 녹슨 자물쇠를 살살 따 본다
  expect: try:door:finesse
  relies: [trait:tinker]
- at: {path: 0, step: 0}
  text: 잠시 숨을 고르며 바다를 바라본다
  expect: look:dock
  known: 1층이 "숨을 고르며"를 시간 보내기(cut)로 확신합니다
```

평가 명령은 전보다 나빠졌는지 잡는 문이다.

- **통과**: 결과가 `expect`와 같고, `relies`를 적었으면 내놓은 기댈 것도 같다.
- **퇴보**: `known`이 없는 사례가 실패했다. 명령이 실패한다(종료 코드 1).
- **무응답**: 모델이 답하지 않았다(오류나 시간 초과). 해석에 대해 알려 주는 것이 없으므로 이것도 실패다.
- **고쳐짐**: `known` 사례가 통과했다. 실패가 아니다. `known`을 지우라고 목록에 나온다.
- **아슬아슬**: 문턱으로 정해진 답의 확률이 문턱에서 0.05 안이다. 프롬프트나 모델이 조금만 바뀌어도 뒤집히므로 확률과 함께 목록에 나온다. 첫 걸음, 행동의 빈칸, 기본값이 아닌 말투·무리, 거짓말, 기댈 것 하나하나를 본다. 시도의 대상과 방법은 서술 모델이 고르므로 보지 않는다.
