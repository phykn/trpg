# 온톨로지 공리계

이 엔진의 세계를 공리 다섯 개 위에 세웁니다. 메커니즘(장애물, 태그, 대화, 숨김)은 공리가 아니라 그 위의 **정의**입니다. 엔진이 지켜야 할 성질은 **정리**로 증명하고, 코드는 **증명 의무**를 테스트로 지킵니다.

```
정의 (2절)
  └ 공리 5개 (3절)                  ← 바뀌지 않음, 서로 독립
      ├ 증명 의무 11개 (4절)         ← 엔진과 원고가 지킬 조건, 테스트가 됨
      ├ 정리 9개 (5절)              ← 공리와 의무로 증명됨
      └ 모형: 어휘 Σ와 정의 (6~7절)  ← 공리와 의무를 지키는 한 바꿀 수 있음
```

메커니즘을 고칠 때의 질문은 하나입니다. **공리와 증명 의무를 지키는가.** 지키면 정리는 그대로 성립합니다.

## 2. 정의

### 2.1 어휘와 원자

- `𝒯`: 개체 종류의 유한 집합.
- `𝒱`: 값 종류의 유한 집합. 각 값 종류는 유한 집합입니다(예: `−3…3`, `0…999`, `{유리, 불리}`). **수의 범위는 값 종류에서 정합니다.**
- `Σ`: 술어 기호의 유한 집합. 기호마다 각 자리의 종류(`𝒯` 또는 `𝒱`)가 정해집니다.
- `U`: 개체의 유한 집합. `τ: U → 𝒯`가 종류를 줍니다.
- `Atom`: 자리마다 종류가 맞는 바닥 원자 `P(c₁,…,cₙ)` 전체. `Σ`, `U`, `𝒱`가 유한하므로 유한합니다.
- **상태** `S ⊆ Atom`. `S ⊨ φ`는 원자 `φ`에 대해 `φ ∈ S`이고, 변수가 `U`나 값 종류 위를 도는 1차 문장에 대해서는 보통의 방식으로 정의합니다(닫힌 세계의 에르브랑 의미론).
- **적합성** `C`: `Σ` 위의 문장 집합.
- **변경** `Δ = (Δ⁺, Δ⁻)`, `Δ⁺, Δ⁻ ⊆ Atom`, `Δ⁺ ∩ Δ⁻ = ∅`. `S ⊕ Δ = (S ∖ Δ⁻) ∪ Δ⁺`.

### 2.2 행동, 사건, 기록

- **행동** `a`: 엔진 스키마 `σ`에 인자를 채운 것. 스키마마다 조건 `pre(σ)`가 있습니다. 모든 행동의 집합 `Act`는 유한합니다.
- **주사위** `rₜ = H(seed, t)`. `H`는 값이 유한 집합(주사위 결과들)인 고정 함수, `seed`는 게임마다 정하는 수입니다.
- **규칙** `R(S, h, a, r) = (Δ, mods)`. `Δ`는 변경, `mods ⊆ Atom`은 판정을 보정한 원자들입니다.
- **사건** `e = (t, a, r, Δ, W, mods)`. `W = W(S, a, Δ) ⊆ U`는 목격자입니다.
- **기록** `L`: 사건의 열. `L₀ = ε`.
- **이력 요약** `h(L)`: 유한 집합 `Pat`(원고와 엔진이 선언한 사건 패턴들)의 부분집합. `h(L) = { π ∈ Pat | L의 어떤 사건이 π에 맞음 }`. 패턴이 맞는지는 사건의 `(a, r, Δ, W, mods)`로만 정하고 `t`는 보지 않습니다. 한 번 들어간 패턴은 빠지지 않습니다.

### 2.3 관찰과 후보

- **관찰자** `o ∈ U`, 종류 agent. 플레이어는 `p★`.
- **관찰** `Obs = (E, F, B, M, hᵥ)`. `E ⊆ U`는 보는 개체, `F ⊆ Atom`은 보이는 사실, `B`는 믿는 명제들, `M`은 투영된 기억(목격한 사건에서 그때 보인 부분만 남긴 것), `hᵥ ⊆ Pat`은 `M`의 사건이 맞는 패턴들(보이는 이력 요약).
- `V: U × 상태 × 기록 → Obs`. `Vₜ = V(p★, Sₜ, Lₜ)`. 구체적인 정의는 7.2입니다.
- **후보** `K: Obs → P_fin(Act)`는 `(E, F, B, hᵥ)`만 읽습니다. `K(O) = { a ∈ Act | a의 개체 인자는 E 안, 명제 인자는 B 안에 있고 (F, hᵥ) ⊨ pre(a) }`. 값 인자(방식, 태도 등)는 값 종류 안이면 됩니다. 조건은 세계 `(S, h)`가 아니라 보이는 것과 원고 상수(인물의 화제 목록 같은 고정된 매개변수) 위에서 평가합니다. 보이는 막힘이 없으면 막힘이 없다고 보는, 일부러 낙관적인 평가입니다.
- 화면이나 프롬프트에 나가는 조건(인물의 바람, 화제의 공짜 조건, 퀘스트 진행)도 `S`, `h`가 아니라 `Obs` 위에서 평가합니다.
- **외생 입력**: 플레이어의 문장, 이전 모델 출력, 모델의 난수. 모델의 난수는 `S`와 독립입니다.

## 3. 공리

### 공리 1. 일반성

`R`, `V`, `K`, `W`, `h`, `C`는 **일반적**입니다. `p★`를 고정하고 종류를 보존하는 `U`의 임의의 이름 바꾸기 `π`에 대해, `S₀`와 원고 매개변수(원고 행동, 효과, 목표, 명제의 뜻)도 `π`로 옮기면 결과가 `π`로 옮겨집니다.

> 뜻: 엔진은 이야기의 특정 개체를 이름으로 알지 못하고, 원고가 준 구조로만 다룹니다. "이야기와 무관한 엔진"의 정확한 형태입니다.
> 독립성: `U = {p★, u₀}`이고 `R`이 `u₀`를 언급하는 행동에만 원자를 더하는 모형은 다른 공리를 모두 만족하고 이 공리만 어깁니다.

### 공리 2. 전이

```
(Δₜ, modsₜ) = R(Sₜ, h(Lₜ), aₜ, rₜ)        Sₜ₊₁ = Sₜ ⊕ Δₜ
```

`R`은 기록을 이력 요약 `h`로만 읽습니다.

> 뜻: 세계는 이 식으로만 바뀝니다. `R`의 인자가 아닌 것(서술, 모델의 답, 화면)은 세계를 바꾸지 못합니다.
> 독립성: `Sₜ₊₁ = Sₜ ⊕ R(…) ∪ {q}`이면서 기록에는 `R(…)`만 남기는 모형은 이 공리만 어깁니다. `R`이 기록 전체를 읽어 사건 수를 세는 모형은 `h` 조항만 어깁니다.

### 공리 3. 기록

```
Lₜ₊₁ = Lₜ · (t, aₜ, rₜ, Δₜ, W(Sₜ, aₜ, Δₜ), modsₜ)      (Δₜ, modsₜ)는 공리 2의 것
```

> 뜻: 일어난 일은 모두 남고, 덧붙기만 합니다. 기억과 "~한 적이 있다"가 모두 기록의 질의입니다.
> 독립성: 모든 `t`에서 `Lₜ = ε`인 모형은 이 공리만 어깁니다.

### 공리 4. 허용

실행되는 모든 행동은 그때의 후보입니다: `aₜ ∈ K(Vₜ)`. 되묻기, 거절, 확인 요청은 행동이 아니며 `t`를 늘리지 않고 사건을 만들지 않습니다.

> 뜻: 버튼, API로 들어온 행동 id, 해석 결과가 모두 같은 문을 지납니다.
> 독립성: 후보가 아닌 행동을 실행하는 모형은 이 공리만 어깁니다.

### 공리 5. 비간섭

턴 `t`에 엔진이 플레이어에게 건네는 모든 것과 모델에게 건네는 모든 입력은 `(Vₜ, 외생 입력)`의 함수입니다(서술 직후의 것은 `Vₜ₊₁`).

> 뜻: 숨은 사실은 화면, 버튼, 프롬프트, 다시 쓰기 피드백 어디로도 직접 새지 않습니다.
> 독립성: 숨은 원자 `h₀` 하나가 있고 `V(S) = S ∖ {h₀}`인데 화면이 `h₀`의 유무를 표시하는 모형은 이 공리만 어깁니다.

### 공리로 두지 않은 것

공리처럼 보이지만 정의나 정리, 의무로 충분한 것입니다.

| 명제 | 자리 | 이유 |
|---|---|---|
| `U`, `Σ`, 원고는 플레이 중 고정 | 2절 정의 | 상수로 정의했으므로 빈 말 |
| 세계는 원자의 집합 | 2.1 정의 | `⊨`의 정의일 뿐임 |
| 모든 상태는 적합하다 | 정리 2 | 공리로 두면 정리 2가 순환 논증이 됨 |
| `R`은 결정적, 네 인자만 읽음, 원자적 | 공리 2의 식 자체 + 의무 P2, P3 | 수학적 함수에는 당연함. 코드에 대한 의무임 |
| 기록은 지워지지 않음 | 공리 3의 식 자체 + 의무 P4 | 덧붙임 식에서 나옴 |
| 해석은 후보 중 하나를 고름 | 공리 4 | 허용이 더 넓게 덮음 |
| 서술은 세계를 바꾸지 않음 | 정리 4 | 공리 2, 3에서 나옴 |
| 서술 주장은 보이는 것 안 | 품질 기준 Q1 | 어떤 정리도 쓰지 않음, `κ`의 정확도만큼만 성립 |

## 4. 증명 의무

공리는 엔진이 어떤 모양이어야 하는지 말하고, 의무는 코드와 원고가 그 모양을 지킨다는 조건입니다. 각 의무가 테스트나 시작 시 검사가 됩니다.

| | 의무 | 쓰는 곳 | 검사 |
|---|---|---|---|
| P1 | **보존**: 모든 `S ⊨ C`, 모든 `h`, 모든 `r`, 모든 `O`, 모든 `a ∈ K(O)`에 대해 `R`의 `Δ`가 `S ⊕ Δ ⊨ C`. 엔진 스키마와 원고 효과 모두 | 정리 2 | 스키마별 성질 테스트, 무작위 행동열 퍼징 |
| P2 | **결정성**: 코드의 `R`은 `(S, h(L), a, r)` 외에 아무것도 읽지 않음 | 공리 2 | 같은 입력 두 번 → 같은 `(Δ, mods)` |
| P3 | **원자성**: 한 턴의 `Δ`는 전부 적용되거나 전혀 적용되지 않음 | 공리 2 | 복사본에 적용 후 교체, 중간 실패 테스트 |
| P4 | **기록**: 저장된 기록은 덧붙기만 하고, 같은 요청 id는 저장된 결과를 돌려줌 | 공리 3, 정리 1 | 재생 테스트, 영수증 테스트 |
| P5 | **허용 검사**: 상태에 적용하기 전에 `a ∈ K(Vₜ)` 확인. 버튼과 API 포함 | 공리 4 | 후보 밖 id를 보내는 테스트 |
| P6 | **관찰 순수성**: `V`, `K`, 화면, 프롬프트, 다시 쓰기 피드백은 `V`와 외생 입력만 읽음 | 공리 5 | `V`가 같은 두 상태 → 같은 프롬프트와 화면 |
| P7 | **일반성의 대리 검사**: 엔진 코드에 이야기의 id, 이름, 문장이 없음 | 공리 1 | 경계 테스트. 일반성의 문법적 근사일 뿐임 |
| P8 | **원고 적합**: `S₀ ⊨ C`, `p★`는 `S₀`에서 장소 하나에 있음, 원고 매개변수가 `Σ`, `U` 위에서 정의됨, 원고 효과는 `C`를 보존하는 연산(7.4)으로만 씀 | 정리 2, 7 | 시작 시 원고 검증 |
| P9 | **표현의 건전성**: 엔진이 만드는 출력(화면, 사실 목록, 프롬프트)은 `F` 안의 원자만 사실로 주장하고 믿음은 믿음으로 표시. `F ⊆ S`. 서술은 이 의무가 아니라 Q1의 대상 | 정리 6 | 렌더러 테스트 |

엔진 의무(P1~P7, P9, P10)는 **P8을 통과한 모든 이야기**에 대해 성립해야 하는 전칭 명제입니다. 템플릿 이야기로 돌리는 테스트는 그 증거일 뿐 증명이 아닙니다. 공리 1의 일반성은 이름만 다른 이야기 사이에서만 결과를 옮겨 주기 때문입니다. 그래서 시작 시 원고 검증에서 이야기마다 P1과 P10을 무작위 행동열로 확인합니다.

품질 기준(정리가 기대지 않는 측정 목표):

- **Q1 서술 수용**: 서술에서 뽑은 주장 `κ`가 `Vₜ₊₁`로 뒷받침됨(7.6). `κ`를 규칙 검사와 Kev로 근사하므로 비율로 잽니다. 수용 판단은 `Vₜ₊₁`만 읽습니다(공리 5). 지어냄과 누설을 가르는 분류는 `S`를 봐야 하므로 오프라인 분석에서만 하고 모델에게 돌려주지 않습니다.

## 5. 정리

### 정리 1. 재현

모든 `t`에 대해 `Sₜ = S₀ ⊕ Δ₀ ⊕ Δ₁ ⊕ … ⊕ Δₜ₋₁`이고, `Δᵢ`는 `Lₜ`의 `i+1`번째 사건에 들어 있습니다. 따라서 상태는 원고와 기록만으로 다시 만들어지며, `R`도 `seed`도 모델도 필요 없습니다. 또 `(이야기, seed, a₀…aₜ₋₁)`이 같으면 `Sₜ`, `Lₜ`가 같습니다.

*증명*: 공리 2, 3을 `t`에 대해 귀납합니다. `L₀ = ε`에서 시작해 각 단계에서 공리 3이 공리 2의 `Δₜ`를 기록에 남깁니다. 두 번째 주장은 `R`(그 값 `(Δ, mods)` 전체), `H`, `W`, `h`가 함수이므로 같은 귀납으로 나옵니다. ∎

*따름*: 기록에서 다시 만드는 경로는 엔진 버전이 바뀌어도 남습니다(`R`을 다시 돌리지 않으므로). 같은 요청 id가 같은 결과를 주는 것은 이 정리가 아니라 P4(영수증)에 기댑니다. 해석은 모델이라 같은 문장이 다른 행동으로 갈 수 있기 때문입니다.

### 정리 2. 적합성

P1, P8 아래에서 모든 `t`에 대해 `Sₜ ⊨ C`입니다. 모델이 어떤 답을 내도 마찬가지입니다.

*증명*: `t`에 대한 귀납. 기저: P8에 따라 `S₀ ⊨ C`. 단계: 공리 4에 따라 `aₜ ∈ K(Vₜ)`이고, P1에 따라 `Sₜ ⊕ R(…) ⊨ C`이며, 공리 2에 따라 그것이 `Sₜ₊₁`입니다. 되묻기, 거절, 확인은 공리 4에 따라 상태를 바꾸지 않습니다. 증명 어디에도 모델의 출력이 들어가지 않습니다. ∎

### 정리 3. 비창조

모든 `t`에 대해 `Sₜ ⊆ Atom(Σ, U, 𝒱)`이고 `U`, `Σ`는 처음과 같습니다.

*증명*: 2절에서 `U`, `Σ`, `𝒱`는 상수로 정의되었습니다. 2.1에 따라 `R`의 값은 `Atom` 위의 변경입니다. 공리 2로 귀납합니다. ∎

### 정리 4. 모델 영향의 한계

모델의 출력이 세계에 영향을 주는 길은 하나뿐입니다. 다음 턴의 행동 `aₜ`가 무엇인지에 영향을 주는 것이고, 그 행동은 `K(Vₜ)`의 원소입니다.

*증명*: 공리 2, 3에 따라 `Sₜ₊₁`과 `Lₜ₊₁`은 `(Sₜ, Lₜ, aₜ, rₜ)`의 함수입니다. `rₜ`는 `H(seed, t)`이고, 모델의 출력은 이 넷 중 `aₜ`에만 들어갈 수 있습니다. 공리 4에 따라 `aₜ ∈ K(Vₜ)`입니다. ∎

*따름*: 서술은 세계를 바꾸지 않습니다. 해석이 틀리면 플레이어가 원하지 않은 후보가 실행될 뿐, 후보 밖의 일은 일어나지 않습니다.

### 정리 5. 비누설

두 상태 `S`, `S'`와 기록이 같은 관찰 `Vₜ`를 주고 외생 입력(플레이어 문장, 이전 모델 출력)도 같으면, 턴 `t`에 플레이어와 모델이 받는 것은 같습니다(서술은 분포로서 같습니다). 숨은 사실이 플레이어에게 닿는 길은, 행동의 결과로 이후의 관찰 `Vₜ₊₁, Vₜ₊₂, …`가 달라지는 것뿐입니다.

*증명*: 첫 주장은 공리 5입니다. 서술은 모델의 난수를 거치지만 그 난수는 `S`와 독립이므로 분포가 같습니다. 둘째 주장: 공리 5에 따라 플레이어가 받는 것은 매 턴의 관찰과 외생 입력의 함수이고, 관찰이 바뀌는 길은 공리 2의 전이뿐입니다. ∎

예: 숨은 경비가 지키는 물건은 후보에 `take`로 나옵니다. 고르면 `R`이 "막힘"을 돌려주고 경비가 드러납니다. 숨은 것을 아는 길은 행동해서 겪는 것입니다.

### 정리 6. 한 근원

P9 아래에서, 한 시점에 엔진이 만드는 화면, 후보, 사실 목록, 프롬프트가 사실로 주장하는 것은 모두 `F`에 들어 있고 `F ⊆ S`이므로 함께 참입니다. 따라서 서로 어긋나지 않고 `C`도 어기지 않습니다.

*증명*: P9에 따라 각 출력이 사실로 주장하는 원자의 합은 `F`에 들어 있고, `F ⊆ Sₜ`입니다. 정리 2에 따라 `Sₜ ⊨ C`이고, 6.3에 따라 `C`는 부분집합에서도 성립하므로 `F ⊨ C`입니다. ∎

해석은 `Vₜ`를 보고 서술은 `Vₜ₊₁`를 봅니다. 두 시점은 다르며, 그 차이가 이번 턴의 변경입니다.

### 정리 7. 이야기 독립

엔진 의무가 성립하면, P8, P11을 통과한 모든 이야기에서 정리 1~6, 9가 성립합니다.

*증명*: 각 증명이 쓰는 것은 공리, 엔진의 의무 P1~P7·P9·P10, 그리고 이야기에 걸린 의무 P8·P11뿐입니다. 엔진 의무는 4절에서 P8을 통과한 모든 이야기에 대한 전칭 명제로 정했습니다. P1이 원고 효과에 대해서도 성립하는 것은 P8이 원고 효과를 `C`를 보존하는 연산으로만 쓰게 하기 때문입니다. ∎

### 정리 8. 도달성 판정

"시작 상태에서 목표 `G`를 만족하는 상태에 닿을 수 있는가"는 판정 가능합니다. 단, 주사위를 비결정적으로(모든 결과가 가능하다고) 봅니다.

*증명*: 구성을 `(S, h, hᵥ)`로 둡니다. 그 수는 많아야 `2^|Atom| · 4^|Pat|`로 유한합니다. 공리 2에 따라 다음 `S`와 새 사건은 `(S, h, a, r)`로 정해지고, `a`는 `K`에서, `r`는 `H`의 유한한 값에서 고릅니다. `K`는 `(E, F, B, hᵥ)`만 읽고 그것은 `S`와 `hᵥ`로 정해집니다(7.2). 다음 `h`와 `hᵥ`는 지금 값과 새 사건(그리고 그때의 `E`)으로 정해집니다. 패턴은 `t`를 보지 않으므로 구성에 `t`가 필요 없습니다. 목표가 `(S, h)` 위의 조건이면 유한 그래프의 도달성 문제입니다. ∎

*주의*: 판정 결과를 늘 성공으로 가정하면 실패로만 닿는 목표(위험이 다 참, 막힘이 드러남)를 놓칩니다. 검증은 성공, 대가 있는 성공, 실패를 모두 펼칩니다. 상태를 줄이려면 목표의 조건, 그 조건을 바꾸는 행동의 `pre`, 그 인자를 보이게 하는 원자까지 거슬러 올라간 영향 범위만 남깁니다.

`U`가 유한하므로 조건에 변수가 있어도 바닥화하면 같은 논증이 됩니다.

### 정리 9. 진행성

P8, P10, P11을 통과한 이야기에서, 매 턴 실행할 수 있는 행동이 있고, 서술은 끝나며, 플레이가 어디에 와 있든 어떤 결말에 닿는 행동열이 있습니다(주사위가 허락하면).

*증명*: P10에서 `K(Vₜ) ≠ ∅`이고 서술이 끝납니다. 지금 구성은 시작에서 닿은 구성이므로 P11(막다른 길 없음)과 정리 8에 따라 거기서 결말에 닿는 구성 경로가 있습니다. 그 경로의 행동이 후보인 것은 P11의 탐색이 `K`로 펼치기 때문입니다. ∎

## 6. 모형: 어휘

여기부터는 공리와 의무를 지키는 한 가지 선택입니다.

### 6.1 종류

- 개체 종류 `𝒯 = { agent, place, thing, obstacle, prop }`
  - `agent`: 플레이어, 인물, 무리(장소 없는 agent)
  - `place`: 장면이 벌어지는 곳
  - `thing`: 놓이거나 들리는 물건
  - `obstacle`: 칸이 차오르는 것. 장애물 진행, 장의 위험, 퀘스트 진행
  - `prop`: 명제
- 값 종류 `𝒱`: `호감 = −3…3`, `칸 = 0…6`, `수량 = 0…999`, `방식 = {힘, 솜씨, 꾀, 매력}`, `태그 = {유리, 불리}`, `수명 = {장면, 장}`, `슬롯 = 1…3`, `시트 항목`, `플래그 이름`, `플래그 값`(모두 유한, 원고가 선언하는 것 포함)

### 6.2 술어

| 술어 | 자리 | 뜻 |
|---|---|---|
| `at(x, y)` | (agent∣thing∣obstacle, place∣agent) | x가 y에 있다. y가 agent면 지님 |
| `link(p, q)` | (place, place) | p에서 q로 갈 수 있다 |
| `blocks(o, x)` | (obstacle, agent∣place∣thing∣obstacle) | o가 x를 막는다 |
| `mark(x, k, l, i)` | (agent∣place∣thing∣obstacle, 태그, 수명, 슬롯) | x에 걸린 태그 하나 |
| `believes(g, p)` | (agent, prop) | g가 p를 믿는다 |
| `regards(g, h, n)` | (agent, agent, 호감) | g가 h를 보는 눈 |
| `fill(o, n)` | (obstacle, 칸) | o의 찬 칸 |
| `stat(g, s, n)` | (agent, 시트 항목, 수량) | 방식 값, 상처, 돈, 기술·특성 보유 |
| `flag(f, v)` | (플래그 이름, 플래그 값) | 이야기 고유의 상태. 최소한만 |

### 6.3 적합성 `C`

- **C1 한 곳**: agent·thing·obstacle마다 `at(x, ·)`는 많아야 하나
- **C2 함수성**: `regards(g, h, ·)`, `fill(o, ·)`, `stat(g, s, ·)`, `flag(f, ·)`, `mark(x, ·, ·, i)`는 각각 많아야 하나
- **C3 칸 상한**: `fill(o, n)`이면 `n ≤ o`의 칸 수(원고 매개변수)
- **C4 무리**: 무리는 `at`이 없음

종류 검사는 `Atom`의 정의에 들어 있으므로 따로 두지 않습니다. 모든 제약이 전칭 부정 문장("이런 원자 조합은 없다")이라 부분집합에서도 성립합니다. "플레이어는 늘 장소 하나에 있다" 같은 존재 조건은 이 성질이 없으므로 `C`에 넣지 않고, P8(시작)과 7.4(`move(p★, ·)`는 장소로만)로 지킵니다.

## 7. 모형: 정의

### 7.1 명제와 앎

이야기는 명제 `p`마다 다음을 줍니다.
- `text(p)`: 모델에게 건네는 문장
- `⟦p⟧`: 뜻. `Σ` 위의 문장이거나, 구조가 없는 서사 명제면 원고가 정한 참·거짓 상수
- `about(p)`, `shows(p) ⊆ U`: 무엇에 대한 말인가, 믿으면 무엇이 보이는가
- `against(p)`: 함께 믿을 수 없는 명제들

정의:
- **참**: `true(p, S) ⟺ S ⊨ ⟦p⟧`. 세계가 바뀌면 명제의 참거짓도 바뀝니다.
- **앎**: `knows(g, p, S) ⟺ believes(g, p) ∈ S ∧ true(p, S)`. 저장하지 않습니다.
- **숨음**: `hidden(x, o, S) ⟺ x ∈ ⋃ₚ shows(p) ∧ ∀p. (x ∈ shows(p) → believes(o, p) ∉ S)`. 보여 주는 명제가 있는 개체는 그중 하나라도 믿기 전까지 숨습니다.
- **들통**: 플레이어가 대화에서 원고 명제 `p`를 주장했고 듣는 이 `h`가 `against(p)`의 명제를 믿으면 들통입니다. 원고 명제에 맞지 않는 주장은 사건에 문장으로만 남고, 들통의 근거가 되지 못합니다. 들통의 근거는 원고만 만듭니다.

### 7.2 관찰 `V`

`here(o)`는 `at(o, q) ∈ S`인 장소 `q`입니다. 관찰자 `o`가 **보는 개체** `E(o, S)`는 지금 지각하는 것만입니다.
- `o` 자신과 `o`가 지닌 것
- `here(o)`와, 거기 있는 숨지 않은 개체
- `here(o)`에서 `link`로 이어진 숨지 않은 장소
- `o`가 속한 무리(원고 속성)

믿는 명제로만 아는 멀리 있는 개체는 `E`에 넣지 않습니다. 그 개체는 명제의 문장 속 이름으로만 전해지고, 그 개체에 대한 원자는 보이지 않습니다. 그래야 멀리 있는 물건의 지금 위치를 겪지 않고 따라가거나, 보이는 사실로 거짓 믿음이 조용히 반박되는 일이 없습니다. 명제의 `shows`는 숨음(7.1)을 풀 뿐입니다. 숨은 개체가 지금 장소에 있거나 이어진 곳이면 그때 `E`에 들어옵니다.

**보이는 사실** `F`: `S`의 원자 중 아래 규칙에 맞고 **명제가 아닌 개체 자리가 모두 `E` 안에 있는** 것. 명제 자리는 `E`가 아니라 아래의 술어별 규칙(`believes`는 `g = o`)이 다룹니다. 그래서 `F ⊆ S`입니다. 이 규칙을 `F규칙(o, S)`라 씁니다.

| 술어 | 보이는 조건 |
|---|---|
| `at`, `link`, `blocks`, `mark`, `fill` | 개체 자리가 모두 `E` 안 |
| `stat(g, ·)`, `believes(g, ·)` | `g = o` |
| `regards(g, h, ·)` | `g = o` 또는 `h = o`(남이 나를 보는 눈은 태도로 드러남) |
| `flag` | 보이지 않음(원고 조건에만 씀) |

**믿음** `B = { p | believes(o, p) ∈ S }`. 각 `p`의 `text(p)`를 건네되 `⟦p⟧`를 `F`에 섞지 않습니다. 믿음은 거짓일 수 있으므로 사실과 따로 표시합니다.

**기억** `M`: `o ∈ W`인 사건마다 `(t, a, r, W ∩ Eₑ, Δ ∩ F규칙ₑ, mods ∩ F규칙ₑ)`. `Eₑ`는 사건 직전과 직후의 `E(o, ·)`의 합입니다. `F규칙ₑ`는 사건 직전과 직후 상태에서의 `F규칙(o, ·)`의 합입니다. 즉 **그때 보인** 원자만 남깁니다. 사건 전후의 상태는 기록에서 다시 만들어지므로(정리 1) `M`은 기록의 함수입니다.

**보이는 이력** `hᵥ`: `M`의 사건이 맞는 패턴들. 패턴은 사건의 투영된 내용으로 판정합니다. 사건마다 한 번 정해지고 바뀌지 않으므로 `hᵥ`는 `h`처럼 덧붙기만 합니다.

**남의 것을 플레이어에게 보일 때**: 모델 프롬프트에 인물 `g`의 기억을 넣을 때는 `M(g)`를 다시 플레이어의 규칙으로 거릅니다. 사건마다 `Δ ∩ F규칙ₑ(g) ∩ F규칙ₑ(p★)`입니다. 플레이어가 함께 보지 않은 사건은 "그 인물이 겪은 일"이라는 사실만 남고 내용은 빠집니다. 공리 5에 따라 모델 입력은 `Vₜ = V(p★, …)`의 함수여야 하기 때문입니다.

### 7.3 행동

엔진 스키마는 여섯 개입니다. 원고 행동과 해법은 `try`에 이름과 추가 조건을 붙인 인스턴스입니다.

| 스키마 | 인자 | `R`의 결과 |
|---|---|---|
| (모든 스키마) | 개체 인자는 `E`, 명제 인자는 `B`, 값 인자는 값 종류 안(2.3) | 조건은 `(F, hᵥ)`와 원고 상수 위에서 평가 |
| `go(q)` | `link(here, q) ∈ F` | 숨은 막힘이 있으면 막은 것이 드러남(그것을 보여 주는 명제를 믿음), 아니면 이동하고 장면 태그 만료 |
| `look(x)` | `x ∈ E` | `x ∈ about(p)`인 명제를 믿음 |
| `take(x)` | `at(x, here) ∈ F` | 숨은 막힘이 있으면 드러남, 아니면 `at(x, o)` |
| `give(x, h)` | `at(x, o)`, `at(h, here)` ∈ F | `at(x, h)`, 원고의 반응 |
| `talk(h, 화제, 태도)` | `at(h, here) ∈ F` | 명제 공개, `regards` 변화, 주장 |
| `try(x, 방식)` | `x ∈ E`, 조건 없음(`pre = ⊤`) | x가 `p★`면 판정 없이 아무것도 바뀌지 않음(대상 없는 즉흥), 장애물이면 `fill` 증가, 불리한 `mark`면 제거, 그 밖이면 판정해서 유리한 `mark` 생성 |

- `pre`는 `(F, hᵥ)` 위에서 평가하지만 `R`은 `(S, h)`를 보고 판정합니다. 그래서 `R`은 보이는 조건은 참이지만 실제 조건은 거짓인 경우에도 정의되어야 합니다(막힘이 드러나는 결과).
- **즉흥 행동**은 언제나 `try(x, 방식)`입니다. `p★ ∈ E`는 늘 참이고 `try`에는 조건이 없으므로 `try(p★, ·)`가 늘 후보에 있습니다. 이것이 P10의 `K ≠ ∅`이고, 대상 없는 즉흥은 아무것도 바꾸지 않으므로 공짜 이득이 없습니다. 즉흥으로 바뀔 수 있는 것은 `fill`과 `mark`뿐이고, 물건, 명제, 길은 장애물이 다 찼을 때의 원고 효과로만 얻습니다.
- **판정 보정**은 모두 원자에서 옵니다(`stat`의 방식 값, 대상의 맞는/어긋나는 방식, `mark`, 지닌 물건, 특성·기술). 보정한 원자는 사건의 `mods`에 남습니다.
- **태그 슬롯**이 다 찼으면 가장 낮은 번호의 슬롯을 비우고 그 자리에 만듭니다.
- **목격자** `W`: 행동 전후로 행위자가 있던 장소에 있던 agent들(`go`면 떠난 곳과 도착한 곳 모두).

### 7.4 효과와 조건

**효과**는 원고가 세계를 바꾸는 유일한 언어이며, 모두 `C`를 보존하는 연산입니다(P8).

**합성**: `R`은 효과 연산들을 차례로, 매번 **앞 연산이 적용된 상태**를 읽으며 적용합니다. 두 변경의 합성은 `Δ⁺ = (Δ₁⁺ ∖ Δ₂⁻) ∪ Δ₂⁺`, `Δ⁻ = (Δ₁⁻ ∖ Δ₂⁺) ∪ Δ₂⁻`이고, 이 합성은 서로소를 유지합니다. 각 연산이 `C`를 보존하므로 차례로 합성한 것도 보존합니다. 같은 턴에 같은 물건을 두 번 옮겨도 `at`은 하나만 남습니다.

| 연산 | 변경 | 보존하는 제약 |
|---|---|---|
| `move(x, y)` | `at(x, ·)`를 빼고 `at(x, y)`를 더함. `x = p★`면 `y`는 장소여야 함 | C1, C4(무리는 대상 불가), 플레이어의 위치 |
| `set(술어, 키, 값)` | 같은 키의 옛 원자를 빼고 새 원자를 더함(`regards`, `fill`, `stat`, `flag`). 값이 같으면 아무것도 하지 않음 | C2, C3(범위를 넘으면 상한에서 멈춤), 서로소 |
| `reveal(g, p)` | `believes(g, p)`를 더함 | - |
| `tag(x, k, l)` / `untag(x, i)` | 슬롯 규칙(7.3)대로 `mark`를 더하거나 뺌 | C2 |
| `link`/`unlink(p, q)` | `link`를 더하거나 뺌 | - |

장 전환과 결말은 `set(flag, 장, …)`, `set(flag, 결말, …)`입니다.

**조건**은 `(S, h)` 위의 문장입니다. 원자, 수 비교, 이력 패턴(`π ∈ h`)을 `all`/`any`/`not`으로 묶습니다. 퀘스트 완료, 장 목표, 결말, 인물의 바람과 두려움, 해법의 조건, 화제의 공짜 조건이 모두 같은 언어입니다.

### 7.5 기억

인물 h의 기억은 h의 관찰 `M`에서 가장 최근 다섯 사건이고, 프롬프트에 넣을 때는 7.2대로 플레이어의 규칙으로 한 번 더 거릅니다. 기억은 프롬프트에만 쓰고, `R`이나 조건은 기억이 아니라 이력 요약 `h(L)`만 읽습니다(공리 2). 같은 장소에서 본 것은 h도 압니다. 따로 "들킨다" 규칙이 없어도 본 사람이 반응합니다.

### 7.6 서술

- **태그 이름**: 서술이 붙인 이름은 `(mark 원자, 만들어진 턴)`을 키로 하는 표현층 표에 둡니다. 슬롯이 다시 쓰여도 옛 이름이 새 태그에 붙지 않습니다. 이름은 그 원자가 `F`에 있을 때만 보여 줍니다. `R`과 조건은 이 표를 읽지 않습니다(공리 2). 화면과 이후 프롬프트가 이 이름을 쓰는 것은 이전 모델 출력, 즉 외생 입력을 쓰는 것이라 공리 5와 맞습니다. 이름이 없으면 엔진의 기본 이름을 씁니다.
- **주장 추출** `κ`는 서술에서 `Σ`의 리터럴(원자와 그 부정)을 뽑습니다. 이름과 별칭(이야기), 술어의 한국어 틀(엔진)로 명백한 것을 먼저 잡고, 나머지는 Kev가 판단합니다.
- **수용**(Q1): `F'`를 `Vₜ₊₁`의 사실이라 할 때, 양의 리터럴 `φ`는 `φ ∈ F'`일 때만, 부정 리터럴 `¬φ`는 `F'`와 `C`에서 `¬φ`가 따라 나올 때만(예: `at(key, A) ∈ F'`이면 C1에서 `¬at(key, B)`) 받습니다. 그 밖의 부정 주장("여기엔 경비가 없다")은 숨은 경비가 있을 수 있으므로 받지 않거나, 인물의 지각("당신 눈에는 보이지 않는다")으로만 씁니다.
- **묘사의 자유**: `Σ`로 옮길 수 없는 문장(냄새, 날씨, 표정)은 이론 안에서 참도 거짓도 아니어서 어떤 상태와도 모순되지 않습니다. 다만 `κ`가 놓친 `Σ` 주장은 검사를 빠져나가므로, 이 자유는 `κ`가 완전할 때만 정확합니다. `Σ`를 키우면 검사 범위가 넓어지고 서술의 자유가 줄어듭니다.
- **끝맺음**(P10): 다시 쓰기는 두 번까지입니다. 그래도 받지 못하면 마지막 시도에서 받지 못한 주장이 든 문장을 지우고 내보냅니다. 다 지워지면 서술 없이 이번 턴의 변경만 화면에 남습니다. 이때의 변경도 기억과 같은 규칙으로 투영한 것(`Δₜ ∩ F규칙ₑ(p★)`, 턴 직전과 직후의 합)입니다. 날것의 `Δ`는 숨은 변경을 담고 있습니다.
