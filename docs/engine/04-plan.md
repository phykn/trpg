# 구현 계획

**새 게임을 어떤 차례로 만드는가**를 정한다. 무엇을 만드는지는 [game/](../game/), [data/](../data/), 이 폴더의 앞 문서들이 정한다. 옛 엔진은 없앤다. 그 코드는 git 기록에 남고, [old/](../old/)의 문서와 함께 참고로만 본다.

## 한눈에

- 단계는 0부터 8까지 아홉이다. 단계마다 **돌아가는 것**과 **시험**이 남는다. 다음 단계는 앞 단계 위에 쌓는다.
- 가장 큰 위험인 **카나나가 알아듣기를 해내는가**를 먼저 본다(1단계).
- 규칙은 모델 없이 시험한다. 모델이 필요한 것은 1, 6, 8단계뿐이다.
- 옛 코드는 0단계에서 지우고, 남길 것만 남긴다.

## 1. 남길 것과 지울 것

| | 남긴다 | 지운다 |
|---|---|---|
| **서버** | `config.py`, `run_api.py`, `models/`(카나나와 gemma4에 맞게 고친다), `api.py`의 인증과 틀, `onto/save.py`의 한꺼번에 쓰기 | `onto/`의 나머지, `rules/`, `story/`, `lang/`, `interpret.py`, `narrate.py`, `cards.py`, `jobs.py`, `view.py`, `service.py`, `fun.py`, `locale/ko.py`의 옛 글, 옛 시험 |
| **화면** | `components/ui/`(단추, 아이콘, 시트, 알림, 움직임, 대화 상자), `design/`, `logic/useViewportHeight.ts`, `services/storage.ts`, Expo와 NativeWind 설정 | `components/game/`, `screens/`, `logic/useGame.ts`, `logic/reveal.ts`, `logic/useLog.ts`, `services/api.ts`와 `types.ts`, `locale/ko.ts`의 옛 글, 옛 시험 |
| **그 밖** | `app/`(Mac 앱), `qa/`의 틀(`common.py`, `decision/bench.py`, `play/`) | `scenarios/skeleton`, `scenarios/pass`, `qa/`의 옛 결과와 옛 엔진에만 맞는 것 |

- 남기는 것도 새 문서에 맞지 않는 곳은 고친다.
- `saves/`의 옛 판은 읽지 않는다(data/05 4절). 지우지는 않고 둔다.

## 2. 단계

### 0. 비우기

- 1절의 "지운다"를 지운다. 서버와 화면이 빈 채로 켜지게 한다. `GET /health`만 답한다.
- **CLAUDE.md, README, `server/README.md`, `client/README.md`, `qa/README.md`를 새 구조로 고친다.** 설계 문서는 `docs/game`, `docs/data`, `docs/engine`이고, 판단 모델은 카나나, 서술 모델은 gemma4다.
- 끝: 시험이 빈 채로 통과한다. `ruff`, `tsc`, `lint`가 깨끗하다.

### 1. 카나나 미리 보기

2026-11-15에 문장 14개로 먼저 보았다. 묻는 법을 정했고 13개를 맞혔다(engine/01 6절). 남은 것은 문장을 늘려 문턱과 화제 둘의 셈을 정하는 일이다.

- 첫 이야기([game/10](../game/10-first-story.md))의 사람과 화제로 알아듣기 물음(engine/01 1절)을 만든다. 시험 문장 50개 안팎에 기대하는 보기를 단다.
- `qa/decision/bench.py`로 카나나에 돌린다. 맞힘, 되묻기, 틀림의 몫을 본다.
- 카나나의 판과 서버 이름, `/v1/systemone`으로 묻는지를 여기서 확인한다(engine/01 6절).
- 끝: 결과를 `qa_test/runs/<run>/`에 남긴다. 틀림이 많으면 2단계에 앞서 묻는 법을 고친다. 묻는 말을 늘리거나, 물음을 쪼개거나, 문턱을 바꾼다.

### 2. 이야기

- data/02의 모양을 읽는 틀과, 굳히기와 판본 표지(02 6절)를 만든다.
- **뼈대 이야기**를 새로 쓴다. 모든 장치를 한 번 이상, 가장 작게 쓴다. 곳 셋, 사람 셋, 거짓말과 꺼림과 잠김 하나씩, 번진 일 하나다.
- 첫 이야기를 `scenarios/<폴더>/story.yaml`로 옮긴다.
- 끝: 두 이야기를 읽고 "가리키는 것이 있다"를 통과한다.

### 3. 규칙

- 판 상태(data/03 1절), 셈해서 얻는 것(03 2절), 바뀐 것과 그 쓰기(data/04 1절), 행동마다의 바뀐 것(04 3절), 적기(04 4절), 시간(04 5절의 4), 지키는 것(data/05 1절)을 만든다.
- 모두 순수 함수다. 주사위는 씨앗과 턴에서 나온다.
- 끝: 뼈대 이야기로 game/05, 06의 규칙을 하나씩 시험한다. 같은 행동 목록을 두 번 넣으면 같은 판이 나온다.

### 4. 검사

- engine/03을 만든다. 3단계의 셈을 그대로 쓴다.
- 이야기 하나를 검사하는 명령을 둔다.
- 끝: 두 이야기가 모두 통과한다. 첫 이야기의 가장 짧은 길이 3칸으로 나온다. 일부러 망가뜨린 이야기(단서 하나를 빼는 것 같은)마다 맞는 검사가 떨어지는지 본다.

### 5. 저장과 API

- data/05의 저장 파일, 다시 열기, 영수증을 만든다.
- engine/02의 길을 만든다. `view`와 `feed`의 한국어는 서버가 만든다.
- 모델 자리에는 시험용 가짜를 끼운다. 가짜는 시험 안에서만 쓰고, 서버를 모델 없이 켜는 길은 두지 않는다.
- 끝: 시험이 판을 열고, 능력치를 고르고, 첫 이야기를 주사위 없이 결론까지 간다. 서버를 껐다 켜도 같은 판이 열린다. 같은 영수증을 두 번 보내도 한 번만 처리한다.

### 6. 모델

- 카나나로 알아듣기와 글 검사를, gemma4로 대답과 장면을 붙인다(engine/01).
- 이야기마다 알아듣기 시험 목록을 두고(engine/01 5절), 1단계의 문장을 옮긴다.
- 끝: 모델을 띄운 채 시험을 돌려 맞힘의 몫과 글 검사에 떨어진 몫을 남긴다. 서버는 켜질 때 두 모델을 확인한다.

### 7. 화면

- game/07의 화면을 만든다. 제목, 시작, 놀이, 수첩, 결론, 결말이다.
- 화면은 engine/02의 `view`를 그대로 쓴다. 누르기는 할 일 id를 보낼 뿐이다.
- 설명하는 글은 없다. 늘 있는 글만 `client/locale/ko.ts`에 둔다.
- 끝: 단위 시험과 함께, 실제 화면을 320×568, 412×915, 데스크톱 폭에서 처음부터 결말까지 해 본다. 턴과 화면을 `qa_test/runs/<run>/`에 남긴다.

### 8. 해 보기

- 쓴 사람이 아닌 사람이 첫 이야기를 한 판 한다(game/08 7절).
- 재미를 보는 지표를 `game/11-fun.md`로 쓴다. 막힘을 연 차례, 헛걸음, 주사위를 건 몫, 결론의 맞음 같은 것이다.
- `qa/play/`를 새 API에 맞춘다.
- 끝: 찾은 것을 `qa/findings.md`에 적고, 숫자(칸 수, 성공률, 문턱)를 고칠지 정한다.

## 3. 단계마다 지키는 것

- **시험을 먼저 돌린다.** 고친 곳의 시험을 먼저, 그다음 건드린 경계의 검사를 돌린다(`pytest`, `ruff`, `npm test`, `tsc`, `lint`).
- **문서와 코드가 어긋나면 문서를 먼저 고친다.** 문서끼리는 game, data, engine 차례로 이긴다.
- **이야기를 고치면 검사를 돌린다.**
- **모델은 띄우지도 끄지도 않는다.** 떠 있다고 보고, 없으면 기다린다.
- 단계 하나가 끝날 때마다 커밋한다.
