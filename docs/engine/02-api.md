# API

**화면과 서버가 주고받는 것**을 정한다. 화면이 무엇을 받는지는 [data/03 3절](../data/03-state.md)이, 한 마디를 처리하는 차례는 [data/04 5절](../data/04-change.md)이 정한다. 화면의 모습은 [game/07](../game/07-screen.md)이 정한다.

## 한눈에

- 화면은 **한 마디**를 보내고, 서버는 그 결과와 새 **화면 상태**(`view`)를 돌려준다. 화면은 받은 `view`를 그대로 쓴다.
- 누르기는 모두 `view`에 든 **할 일의 id**를 돌려보내는 것이다. 무엇을 할 수 있는지, 성공률이 얼마인지는 서버가 셈해 `view`에 넣는다. 화면은 규칙을 모른다.
- 플레이어에게 보이는 한국어는 서버가 만든다. 화면은 고치지 않고 보여 준다. 화면에 늘 있는 글만 `client/locale/ko.ts`에 둔다.
- AI의 글은 따로 **흘려받는다**(5절).
- `GET /health`만 빼고 모든 길에 Basic Auth가 필요하다. `--local`이면 `local/local`이다.

## 1. 길

| 길 | 보내는 것 | 받는 것 |
|---|---|---|
| `GET /health` | | `{ok: true}`. 인증 없이 된다 |
| `GET /stories` | | 이야기 목록. `[{story, title, intro}]` |
| `POST /games` | `{request_id, story}` | `{game, view}` |
| `GET /games/{game}` | | `view` |
| `GET /games/{game}/turns?from={n}` | | 턴 `n`부터의 지난 결과(3절)의 목록. 다시 열 때 대화를 다시 그리는 데 쓴다 |
| `POST /games/{game}/commands` | 2절 | 3절 |
| `GET /games/{game}/turns/{n}/text` | | NDJSON(5절) |
| `GET /games/{game}/turns/{n}/text/poll?after={k}` | | `{events, next}`(5절). 화면은 이것을 쓴다 |

- `story`는 이야기의 이름이다([data/02](../data/02-story.md) 머리). `intro`는 도입 글이다.
- `game`은 판의 이름이다([data/05](../data/05-save.md)). 화면은 이것 하나만 `trpg.game_id`에 기억한다. 불러오지 못해도 지우지 않는다.
- `request_id`는 화면이 한 마디마다 새로 만드는 문자열이다(UUID, 64자까지). 영수증이다([data/05 5절](../data/05-save.md)).

## 2. 한 마디

`POST /games/{game}/commands`에는 `{request_id, revision}`과 아래 가운데 하나를 보낸다.

| 보내는 것 | 뜻 | data/04 2절의 행동 |
|---|---|---|
| `{text}` | 입력칸에 쓴 문장. 말하는 상대에게 묻는다 | 묻기. 알아듣고 옮기기가 될 수도 있다 |
| `{do, text?}` | `view`의 할 일 id. `text`는 입력칸에 쓴 말을 함께 보낼 때 | 옮기기, 둘러보기, 내밀기, 걸기, 상대 고르기, 능력치 고르기 |
| `{read: [줄 id…]}` | 수첩에서 본 줄 | 수첩 읽기 |
| `{conclude: {who, how, why}}` | 결론. 각각 줄 id나 `null` | 결론 내기 |

- `revision`은 `view.revision`이다. 다른 곳에서 판이 먼저 바뀌었으면 409가 온다.
- **할 일 id는 그 `revision`에서만 쓰인다.** 판이 바뀌면 새 `view`의 id를 쓴다.
- **줄 id는 판이 끝날 때까지 바뀌지 않는다.** 수첩의 차례로 매기는 번호다. 이야기의 주소(data/02 4절)는 화면에 보내지 않는다. 주소의 갈래 이름이 거짓말인지를 알려 주기 때문이다.

## 3. 결과

```
{ "kind": "turn" | "refused",
  "turn": 12,                       기록에 쓴 턴. refused면 null
  "said": "징수관이 오늘 왔습니까?",   대화에 남길 플레이어의 말. 단추로 옮겼으면 null
  "feed": [ … ],                    대화에 끼어들 것들. 차례대로
  "text": true,                     흘려받을 AI의 글이 있는가(5절)
  "view": GameView }
```

`feed`의 하나하나:

| `kind` | 담는 것 | 보기 |
|---|---|---|
| `move` | 가름줄의 글 | `── 숲길 · 1턴 ──` |
| `roll` | 방식, 두 눈, 합, 성공했는지 | 달랜다 · 4, 3 · 9 |
| `note` | 수첩 알림의 글과, 누르면 열 줄 id들 | `수첩 · 브람의 말 적음` |
| `omen` | 조짐이 있다는 것. 글은 5절로 온다 | |
| `event` | 번진 일이 벌어졌다는 것. 글은 5절로 온다 | |
| `text` | 5절로 올 AI의 글 한 조각의 자리. 누구의 말인지(사람 이름이나 장면). 결론의 턴에는 지목된 사람의 대꾸가 결말 앞에 온다. 사람의 말이면 `topics`에 그 턴 뒤 아직 듣지 못한 그 사람의 화제 이름들(game/04 5절). 화면은 글 속의 그 이름에 밑줄을 친다 | |
| `guide` | DM이 한마디 한다는 것(game/07 2절). 글은 5절로 온다. 곁의 사람의 화제를 짚는 도움이면 `topics`에 그 이름 하나 | |

- `feed`의 차례가 대화에 보일 차례다. AI의 글은 `text` 자리에 흘러든다.
- **`refused`**: 판도 턴도 그대로다. 할 수 없는 행동(data/04 2절)이나, 지난 `revision`의 할 일 id가 왔을 때다. `code`만 붙고 플레이어에게 보일 글은 없다. 화면은 받은 `view`로 돌아간다.

## 4. `GameView`

화면에 필요한 것 전부다. data/03 3절의 "화면이 받는 것"만 담는다.

| 필드 | 담는 것 |
|---|---|
| `revision` | 다음 한 마디에 함께 보낼 값 |
| `story` | `{story, title}` |
| `stage` | `start`(능력치를 고르기 전), `play`, `closing`(칸이 다 됐다), `over`(결론을 냈다) |
| `start` | `stage`가 `start`일 때. 도입 글, 능력치 넷과 고르는 할 일 |
| `place` | 지금 곳의 이름, 갈 곳 목록, 둘러보는 할 일(`look.id`, 판을 하는 동안만), 이미 둘러봤는가(`looked`). 갈 곳마다 할 일 id, 이름, 드는 칸, 안 가 봄 |
| `time` | 위 띠의 글(`밤 11시 20분 · 14턴`), 남은 칸, 마지막 세 칸인가 |
| `people` | 이곳의 사람. 사람마다 이름, 고른 상대인가, 고르는 할 일 id |
| `notebook` | 다섯 묶음(곳, 사람, 물건, 본 것, 들은 말)의 줄 목록. 아래 표 |
| `offers` | 바로 앞 턴이 글로 쓴 행동이거나 짐작한 행동이었을 때 그 방식으로 걸 수 있는 주사위 단추. 모양은 줄의 `acts`와 같다. 아니면 빈 목록 |
| `badge` | 새로 적혀 아직 읽지 않은 줄의 수(다섯 묶음 모두) |
| `conclude` | 결론에서 고를 수 있는 줄 id들. 누가는 사람 줄, 어떻게와 왜는 단서 줄 |
| `ending` | `stage`가 `over`일 때. 결말 글의 자리(5절로 온다), 세 물음의 맞음과 틀림과 비움, 놓친 것의 글 |

`notebook`의 줄 하나:

| 필드 | 담는 것 |
|---|---|
| `id` | 줄 id |
| `text` | 수첩에 보일 글. 들은 말이면 누구의 말인지도 |
| `marks` | 붙은 표시의 글. `말을 아낀다`, `실마리: …`, `숨기는 것이 있다`, `안 가 봄` 같은 것 |
| `struck` | 그어졌는가 |
| `intro` | 사람과 물건 줄이면 이야기의 소개, 가 본 곳이면 그곳의 모습. 아니면 `null` |
| `about` | 줄을 열면 함께 보일 줄의 id들(game/03 1절). 사람이면 들은 말, 곳이면 그곳에서 본 것(수첩 순서대로), 본 것과 물건이면 있던 곳, 들은 말이면 말한 사람, 그 뒤에 단서가 알려 준 곳과 사람. 적히지 않은 줄은 빠진다 |
| `new` | 아직 읽지 않았는가 |
| `acts` | 이 줄에서 지금 할 수 있는 일. 할 일마다 id와 단추의 글(`달랜다 · 72% · 1턴`, `쇠꼬챙이를 쓴다 · 틀리면 1턴`, `브람에게 내민다 · 아까 통하지 않았다 · 1턴`) |

- `acts`는 game/07 2절의 "줄에서 하는 일" 표대로 서버가 만든다. 할 수 없는 일은 들어 있지 않다.
- 성공률은 단추의 글 안에만 있다. 태도의 값은 어디에도 없다.

## 5. AI의 글

`GET /games/{game}/turns/{n}/text`는 NDJSON이다. 결과의 `feed`에 있던 `text` 자리마다 차례로 흘러온다.

```
{"type": "start", "slot": 0}            slot번째 text 자리의 글이 시작된다
{"type": "delta", "slot": 0, "text": "……알았소, "}
{"type": "replace", "slot": 0, "text": "……"}   검사에 떨어져 다시 쓴 글 전체로 바꾼다
{"type": "end", "slot": 0}
{"type": "done"}                         이 턴의 글이 모두 끝났다. 입력이 풀린다
{"type": "error"}                        서술 모델이 답하지 않았거나 글을 쓰다 다른 탈이 났다
```

- 글은 쓰이는 대로 온다(game/07 2절). 검사(engine/01 4절)는 다 쓴 뒤에 하고, 떨어지면 다시 쓴 글이 `replace`로 온다.
- 이미 만든 글이 있으면 `start`, 글 전체를 담은 `delta`, `end`, `done`이 바로 온다.
- 같은 턴의 글을 동시에 여러 번 청해도 글은 한 번만 만든다. 나머지는 그 결과를 같이 받는다.
- `error`가 오면 판은 이미 바뀌어 있다. 화면은 같은 길을 다시 청한다. 다시 청할 때 이미 쓴 글은 처음부터 다시 쓴다.

**나눠 받기.** 휴대폰 주소가 거치는 Cloudflare 빠른 터널은 흐르는 응답을 끝날 때까지 모아 두었다가 한꺼번에 보낸다(SSE도 같다, 2026-11-16 확인). 그래서 화면은 `text/poll`을 거듭 청한다.

- `after`는 이미 받은 사건의 수다. 답은 그 뒤의 사건(`events`, 위와 같은 모양)과 다음에 보낼 `after`(`next`)다.
- 새 사건이 없으면 2초까지 기다렸다가 빈 `events`로 답한다. 화면은 `done`이나 `error`를 받을 때까지 곧바로 다시 청한다.
- 글이 이미 저장됐으면 `after`와 상관없이 글 전체(`start`, `delta`, `end`, `done`)가 온다. `start`가 자리를 비우고 `delta`가 다시 채우므로 화면은 그대로 받으면 된다.

## 6. 오류

| 오류 | 언제 | 담는 것 |
|---|---|---|
| 404 | 그런 판이나 이야기가 없다 | |
| 409 | `revision`이 낡았다. 같은 `request_id`로 다른 한 마디가 왔다 | `{view}`. 화면은 이 `view`를 쓴다 |
| 409 | 저장이 망가졌거나 옮길 수 없는 옛 형식이다(data/05 3, 4절) | `{reason: "broken" \| "incompatible"}` |
| 422 | 요청의 모양이 틀렸다 | `{reason}` |
| 503 | 판단 모델이 답하지 않았다(engine/01 1절) | 판은 그대로다. 화면은 같은 `request_id`로 다시 보낸다 |

- 같은 `request_id`가 이미 기록에 있으면 오류가 아니다. 그때의 결과를 그대로 돌려준다.
- 답이 오지 않으면 화면은 입력을 잠근 채 같은 한 마디를 다시 보내는 단추만 내준다(game/07 5절). 대답이 흐르는 동안 입력을 잠그는 것도 화면이 한다. 둘 다 `view`에 없다.
- `reason`과 `code`는 화면이 갈래를 가르는 데만 쓴다. 플레이어에게 글로 보이지 않는다.
